# v0.1.0-alpha.1

第一阶段（P1-01…P1-20）收口版。核心命题的**首个可安装形态**：两名以上成员围绕
一个 Task，让不同 Agent 在各自受控的 Workspace 中运行，并安全地观察、审批、接管
和交付结果。

**这是 alpha**：安全策略与协议仍在收口（见「已知限制」），不建议承载真实敏感数据。

## 安装

面向非开发试用者的全链路径：[docs/installation.md](../docs/installation.md)
（Linux Hub / Docker Compose 单机起步 + macOS、Linux Node）。

## 这一版能做什么

- 团队 Setup（一次性 Token）→ 成员邀请 → 设备配对 → Workspace 注册
- Task/Run 全链：排队、分派、Agent 执行（DSH Runtime）、事件实时回放到浏览器
- 审批（approval）与取消升级、结果接管；Artifact 上传与受控下载
- 插件目录（curated catalog）与不可变 Pack 供给、digest 校验
- 断线/重启的会话恢复：Hub 重启、Node 断线、Runtime 崩溃的状态矩阵
- 单源部署（Hub + Web + PostgreSQL，nginx 反代），浏览器只面对一个 origin

## 依赖许可与 SBOM

根许可 Apache-2.0。许可 gate（`pnpm test:licenses`）：强 copyleft 红；弱 copyleft
默认禁、白名单**必须带依赖链与法据**（唯一条目：libvips/LGPL-3.0，经 DSH 官方包
的 sharp 二进制形态，非本项目可换）。SBOM 为 CycloneDX（CI 产物）。

## 升级与回滚

升级与回滚操作见 [docs/installation.md §E](../docs/installation.md)。alpha 期的
关键约束：**数据库迁移只向前**——旧版 hub 遇到新版 schema 会拒绝启动（不坏数据），
真回退需人工。协议包（`packages/protocol`）与 migration 在本阶段冻结，任何变更
走独立 PR + 两人评审。

## 已知限制（alpha 明示，不是漏项）

1. **多人部署需要 TLS**：会话 Cookie 在非 localhost 强制 `Secure`（正确的安全
   默认），因此 `http://192.168.x.x` 形态登录即失效——多人试用用 https 或 SSH
   隧道（安装文档红字）；产品级 LAN 方案在议（#105）。
2. **`start` 运行期间新增 Workspace 需重启 Node 才可见**（#94）：正常顺序「先
   add 后 start」不受影响。
3. **反代形态下速率限制是全队共享预算**：nginx 未传 `X-Forwarded-For`、hub 未开
   trustProxy——所有成员的登录/邀请限流按 web 容器网关 IP 计（一人连错密码可占满
   全队配额；3–10 人 Alpha 可用但不体面）。修复在册（XFF+trustProxy 含开关）。
4. 运行事实的三处语义账未平（诚实账，各有 E2E 兜底或观察项在册）：心跳竞态可致
   新受理 Run 被误标 lost（#87）、终态 Run 不回收 Runtime 可占满设备容量（#88）、
   status_request 应答不 ack 的重发噪声（#90）——见各 Issue 与验收文档的「未闭合」
   条目。alpha 使用者会看到的现象与绕行写在各 Issue 内。
5. 插件开发模式（`PROJECT311_PLUGIN_DEV_MODE`）仅本机可信目录，不做远程加载。
