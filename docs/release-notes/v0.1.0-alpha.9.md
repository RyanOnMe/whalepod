# v0.1.0-alpha.9

> **第二个 GitHub Release**（上一版 Release 是 [v0.1.0-alpha.7](https://github.com/RyanOnMe/whalepod/releases/tag/v0.1.0-alpha.7)，
> 2026-10-10；alpha.8 tag 已推送但未建 Release，原因见下）。目标读者不变：愿意部署 Compose、跑真实双人闭环、并接受 alpha 风险的团队。
> 安装看 [docs/installation.md](../installation.md)；限制声明在本文件末尾，**请连它一起读**。

## 本版主题：让要求和成果准确传到下一个人

alpha.7 的**机器验收**覆盖了同一 Task 内的执行、观察、审批与接管路径；那不是真人可用性
结论。本版补的是**交接**：执行前对要求有共同依据，执行成果能版本化地交给下一个人，
接收方明确知道自己继承了哪一版、哪些材料、下一步准备做什么；同时把执行区从「先选运行
再看面板」改成按时间连续阅读的对话工作区。机器侧把这条闭环一次走完，并给关键边界留下
独立判据；**真人试用仍未开始**，这一条写在限制声明第 1 条，不要读漏。

## 为什么不是 alpha.8

alpha.8 的 tag 已推送、发布材料已合入，但 tag 工作流的 Q5 job 在 **180 分钟作业上限**被取消：
完成 **13/20 全 PASS**（每轮约 13.3 分钟），第 14 轮中途被切断；Q8 短档与 Q9 compose 冒烟
已绿。**这不是测试失败**。20 轮 × 13.3 分钟 ≈ 266 分钟，套件在新增 #381/#393/#415 等链路后
已超出原上限。已把 Q5 job 的 `timeout-minutes` 提到 360（#418），按版本序列发 alpha.9；
alpha.8 tag 保留为历史（与 alpha.5/alpha.6 同一先例）。证据：
[run 39818487786](https://github.com/RyanOnMe/whalepod/actions/runs/39818487786)（Q5 13/20、
Q8/Q9 成功）。

## 相对 alpha.7 的主要变化

### 1. 任务约定与交接闭环（ADR-0017，四批）

- **任务约定版本化（#378）**：`TaskSpecRevision` 固定四段——目标、约束、验收条件、待确认
  问题。草稿不构成要求；只有 Task 真人责任人显式确认后才冻结为已确认版本，版本号按 Task
  单调递增。草稿编辑携带 `draft_version` 并发令牌，不匹配即 409，不覆盖别人的修改。
  Task 级 `agreement_enabled` 开关开启后，业务 Run 必须绑定已确认版本；整理约定的辅助 Run
  以 `purpose='agreement_draft'` 显式标记并免绑定。全部 Run 创建入口（执行区、创建即执行、
  重跑、续跑、Agent 指派）统一走同一绑定规则。
- **执行收尾自动整理交接草稿（#379）**：**正常完成**且 Task 已启用约定
  （`agreement_enabled`）的业务 Run，在 `run.completed` 之前由 Runtime 收尾调用一次模型
  生成六段式交接叙述；**失败/取消的 Run 不调用**，默认 Task 也不自动生成。每 Run 至多
  尝试一次，默认 60 秒上限。草稿只对 Run owner（Task 责任人）可见；其他成员（含管理员）一律
  404。自动生成条目 `verified=false`，owner 人工编辑才可标记已核实。发布产生不可变
  revision，发布校验要求 Task 已启用约定、证据条目附引用、Artifact 必须是本 Task 已发布
  交付物、Run 引用属本 Task。收尾模型失败/超时显示「交接草稿未生成」，**业务结果不受
  影响**。
- **跨 Task 交付与接收确认（#380）**：上游把已发布 revision 交付给同项目成员，并新建或
  关联下游 Task。接收方先读指定正文，再填写「本次准备做什么」确认；确认不等于接受任务，
  也不自动起 Run。差异作为一条讨论消息落在上游 Task。上游出新版本后，接收方需显式
  `adopt`；`expectedRevisionId` 不匹配返回 409，重复确认幂等且不覆盖首次理解。
- **下游 Run 固定交接输入（#380/#396）**：Hub 在创建 Run 时把 `HandoffInputManifest` 冻进
  **Run 行的独立列**（`run.handoff_input`，与 Artifact 输入清单互不合并）。`run.start`
  的交接相关字段只携带 `handoff`（本 Run 的**约定快照**，供收尾生成草稿）与
  `executionContext`；跨 Task 的完整清单由 Node 在 Runtime 启动前通过
  `GET /node/runs/:runId/handoff-input` 读取，复制材料并逐件核对真实字节
  sha256/byteSize。上游后来发 v2 **不会改任何历史 Run 的输入**。
- **正文实际消费与容量边界（#396 / ADR-0020）**：约定/交接正文进入首条指令；约定与交接
  正文合计超过 100,000 字符时，Hub 在装配处返回明确的 400，不落到 wire parse 的 500；
  交接叙述整体上限 24,576 UTF-8 字节。辅助 Run（`agreement_draft` / `handoff_draft`）
  只有责任人能发起。

### 2. 连续对话工作区（ADR-0019 / #393）

- 执行区按 Run 为段连续展示历史指令、Agent 回复与文件卡片，**不需要先选一个运行**；段序
  与服务端运行顺序一致，段内保持事件 `seq`。运行列表不再常驻，落点/时间/版本/血缘/输入/
  Console 收进「运行详情」；取消、继续此会话、重跑也在详情里，避免同一组操作在每一段重复
  出现。
- 「默认继续」是一条规则：无历史默认新执行；有活跃运行默认追问；运行结束后默认续聊最近
  一次业务运行。用户显式选过就不再被改写；来源不可续接时不自动改投，保留草稿并说明原因。
- 分页读取按游标续读，支持 20 段窗口、载入更早的锚点漂移、上翻后新内容不拽人；两个成员
  的浏览器各自读同一张事件表的真子集，受众语义不伪造。
- **设备离线 fail-closed（#394）**：续跑/重跑不再只看「曾经 hello」的版本列。Hub 与设备读面
  共用同一个 30 秒 `lastSeenAt` 在线窗口；来源设备离线、已撤销或从未 hello 时明确拒绝
  （`DEVICE_OFFLINE` / `DEVICE_REVOKED`），**不建 Run、不落指令**；自动三段式目标解析也会
  跳过离线设备。Web 端在默认继续前先挡一次，保留草稿并说清原因。设备重新上线后照常。

### 3. 聚焦任务工作区、个人行动与交付复核（ADR-0018；决策 2 由 ADR-0019 取代）

- 收拢任务工作区的信息层级：主内容聚焦当前任务，详情、历史运行与二级页面进抽屉/独立页；
  减少重复标题与辅助文案，保留可读的落点、版本与状态。
- 首页「需要我处理」按当前用户权限投影接受任务、重新指派、处理审批、检查候选、确认完成；
  点击只定位到任务内对应区域，实际变更仍要真人操作。候选的私有线索不进个人待办投影。
- 补齐创建与执行的表达：责任人 vs「创建后立即执行」分开（#344）；创建成功但启动失败时落到
  原任务的准备环境继续（#345）；准备往返后原文字与设置保留（#337/#338），**刷新、登出、
  会话过期或换人会丢弃草稿**（当前页面会话边界，不声称跨设备/跨登录保存）；返回任务不等于
  已发送，焦点落回执行区（#339）。
- 交付与复核：候选发布前检查（#313）、发布后再请复核（#326）、按明确的生产者上下文修订
  （#327）、固定 Artifact 输入身份（#325）、待处理指令撤销边界（#321）。
- Micro 交互两批（#306/#308/#310）：Warm Tooltip、Bell Toggle、Swipe Toast 等小控件接进
  Task Room，Q5 截图与真实交互证据同批归档；下拉描边判据改为读真实交互态与过渡（#398），
  不再用硬编码的视觉常量冒充浏览器事实。

### 4. 发布前的 Q5 实测修复与门禁硬化

这一版发布前跑了完整 Q5 与多轮复跑，下面每条都是**先红后绿**、有现场证据的修复：

- **#399**：R8 故障窗口改为显式保持「派发前断连」，恢复后由独立判定器核对
  `component='node.gateway'` 与 `blockedConnectionAttempts>=1`，不再用「界面看起来恢复了」
  当结论。
- **#402**：执行区取证的 composer host 稳定化，拒绝时序改为真实交互时序；验收记录明确区分
  失败 attempt 与后续成功运行，不把被覆盖的旧日志当新证据。
- **#403**：同一表单实例内，任务创建提交在成功离开表单前用同步锁挡住重复提交；React
  pending 尚未刷新或导航尚未卸载的窗口也不再建出第二个任务。折叠/取消后重开的跨实例
  旁路不在本版修复范围（已立账，见限制 13）。
- **#394**：见上，续跑/重跑按设备在线窗口 fail-closed；保留 `DEVICE_REVOKED` 与
  `WORKSPACE_UNAVAILABLE` 的专属错误码，不降级成泛化的离线错误。
- **#396**：约定/交接正文真正进入执行上下文；装配超限 fail-closed；采用版本 CAS 增加
  「带当前最新版本必须成功」的正控；Web 采用冲突立即失效并重读回执。
- **#407**：发布预验时发现宿主系统代理/PAC/WPAD 会让 Chrome 首次 `localhost` 导航等
  53 秒（页面最终能加载，但 60 秒测试预算已耗尽）。e2e 改为 Chrome 直连本机，不再被宿主
  网络设置污染；这是**测试装配**修复，不改产品路径。p1-07 用例 57.5s → 3.9s，整项目
  1.2m → 19.6s，完整 Q5 在新树上重跑。
- **#418**：alpha.8 tag 的 `q5-release` Q5 job 在 180 分钟作业上限被取消（**13/20 PASS，
  非测试失败**）；Q5 job 上限提到 360 分钟，按 alpha.9 重跑。详见「为什么不是 alpha.8」。
- 工程收口（alpha.7 tag 之后合入）：#183 测试代码 typecheck 清零并接线、#281 E2E Hub 只走
  包解析 dist、#305 测试进程收尾与残留自检、#352 `node.hello` 按连接重算、#356 换版归因码
  `RUNTIME_VERSION_CHANGED`、#353 cancel 竞态 Q3 判据、#360 纯逻辑用例改文件级 20s 时间
  预算（判定断言未动）、#288/#289/#290 DSH 熔断与能力契约收口。

## 升级与兼容性

- **升级前先备份**（迁移只向前；备份是 DB-only，`hubdata` 的 Artifact 存储不在其中，
  本版迁移也不改它）：

  ```bash
  # 升级前（自定义格式，支持 --clean 恢复）
  docker compose --env-file .env -f deploy/compose.yml exec -T db \
    pg_dump -U postgres -Fc -d whalepod > whalepod-backup-$(date +%F-%H%M).dump
  # 回滚时（先停 Hub，确认没有新连接）
  docker compose --env-file .env -f deploy/compose.yml stop hub
  docker compose --env-file .env -f deploy/compose.yml exec -T db \
    pg_restore -U postgres -d whalepod --clean --if-exists < whalepod-backup-YYYYMMDD-HHMM.dump
  ```

  升级期间不要启动新的 Run；先停 Hub 再重建，确认新版本健康后再清理备份。回滚 =
  停 Hub → 恢复 dump → 切回旧 tag → 重建。Hub 与所有 Node **一起升级**；本版没有对
  混合版本（任一方向）做兼容性验收。
- **从 alpha.7 升级**：切到 `v0.1.0-alpha.9` → Hub 侧
  `docker compose ... up -d --build`；每台 Node 机器
  `pnpm install --frozen-lockfile && pnpm -r --if-present build`，再重启
  `node apps/node/dist/cli.js start`。Node 必须重建：新的 DSH 版本探针与
  `runtime.ready` 的 `profileDigest` 对照点都在新构建里。
- **数据库迁移**：本版新增 0011–0014（Artifact 输入快照、任务约定、交接、交接回执）。Hub
  启动时自动向前迁移；迁移是**只向前**的，回滚到旧 tag 时旧代码不认识新 schema 列，可能
  报错，属预期。需要真回退数据用上面的备份恢复。
- **DSH 兼容闸（#288）**：Node 会用本机 DSH 版本逐包比对 pack 的 `dshCompatibility`；不符
  即 fail-closed（`PLUGIN_PACK_MISMATCH`），不会带着不兼容的 pack 启动。`runtime.ready`
  回报的 `profileDigest` 与固化的 Revision digest 不符时，Run 以 `PROFILE_MISMATCH`
  失败并终止 Runtime。**不要改闸绕开**；要么更新 pack 的兼容声明，要么按 `dsh-upgrade`
  回滚 DSH。本版 DSH 版本与 alpha.7 相同，没有升级 `@deepseek-ai/*`。
- **设备在线口径**：`lastSeenAt` 30 秒内视为在线，Node 需要保持心跳；离线时新执行/续跑/
  重跑会被明确拒绝，这是本版的预期行为，不是「网页坏了」。

## 已知限制（alpha 明示，不是漏项）

1. **真人试用尚未开始**。本版新增的任务约定与交接闭环有**生产装配的机器验收**（真 Hub/
   Node/Runtime，模型出口是 DSH replay 脚本），但没有 **≥2 个真实团队**独立走通的证据
   （计划招募 3 队）；试用包与记录模板已就绪（#381），所有 human 字段仍是 `not_run`。
   机器 PASS 不等于用户能理解、愿意用或省了协作成本。
2. **真实 Provider 的执行质量与费用未测**。replay 只证明装配、协议、状态转换与上下文
   消费；真实模型的延迟、质量、费用、失败率需要试用中的真实密钥。
3. **不声称性能达标**。Q8 仍没有合格的权威判据环境（04 §8 要 4CPU/8GiB Linux 专用机）；
   CI runner 的短档只作趋势证据。Alpha 期正式口径：不声称任何性能指标达标。
4. **Q9 只到凭证边界**。空卷安装、配对、Workspace、双 Run、跨成员拒绝都验；审批、
   Artifact 发布、Reviewer 与验收的产品路径由 Q5 replay 覆盖，真实模型行为需要真密钥与
   外部 alpha。
5. **DSH 仍是 Preview 依赖**。不保证不可信插件的强隔离，不保证外部工具副作用可撤销；
   能力契约六项与熔断四规则都有机器判据，但「真实装另一版再回滚安装树」仍是人工门。
   本版新上的兼容闸与 digest 对照点见「升级与兼容性」。
6. **协议与迁移只向前**。回滚 = 停 Hub + 用备份恢复；旧代码不认识新 schema 列时可能报错，
   不要把版本守卫当保护机制。
7. **测试/脚本类型面仍有残余**。#183 已把四个包/应用的测试 typecheck 清零并接线；但
   `scripts/*.mts` 仍不在任何 typecheck program 内（#373），phase1 chain 的跨包测试
   helper 与接线判据还有残余盲区（#375/#376）。别把「Q0 全绿」读成「所有脚本类型正确」。
8. **多人部署需要 TLS**。会话 Cookie 在非 localhost 强制 `Secure`（#105 裁决维持现状）；
   LAN 试用走内网 CA/自签 https 或 SSH 隧道，指引见 installation。
9. **门禁按风险分级**（G0/G1/G2）。普通 UI 变更不付分布式故障测试成本——这不等于 UI 无
   缺陷，只等于其缺陷不阻塞发布。
10. **单维护者 + AI 自主交付**。协议/migration 类变更走「自查记录留档 + CI 双绿」，
    **不等于第二人评审**；发布前的外部工程师审查仍在争取。
11. **命名冲突未解决**。GitHub 上存在同名不同定位的 `whyihaveyou/whalepod`；公开传播前
    解决（不阻内部/试用）。
12. **附件冻结**（#266）：暂不支持上传附件；不做 Project 级私有 ACL；深色模式（#236）暂缓。
13. **两条小的恢复/重复创建边界**：
    - 任务创建提交在途时折叠/取消表单再打开，可以绕过同一表单实例的同步锁，可能重复创建
      （#411）。
    - 同 `Idempotency-Key` 的 `POST /runs` 在设备离线时会在回执回放前先返回 409
      （#414）：第一次请求可能已经建了 Run，但客户端拿不回它的 id；
      设备在线时同 key 重试会回放回执，离线时只能从运行列表取回。
14. **本机 localhost + 系统代理/PAC/WPAD 可能首屏慢**。如果试用机打开 `localhost` 很慢，
    把 `localhost`/`127.0.0.1` 加入代理例外；e2e 已改为直连（#407），不影响部署后的
    反向代理路径。
