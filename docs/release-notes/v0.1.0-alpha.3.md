## 修复清单（全部有红测与评审实录）

- **#117 / PR #121**（狗食 Bug1）：真模型腿的 provider 路由名与凭证环境名双双与
  真 DSH adapter 不符——dsh-llm-deepseek 注册 `deepseek-official` 且 credential-ref
  默认 `DEEPSEEK_API_KEY`，仓库默认却写 `deepseek` 并派生注入
  `DEEPSEEK_OFFICIAL_API_KEY` → 真 Run 以 NO_ADAPTER / MISSING_CREDENTIAL 败。
  修法：node 侧 provider→credential-ref 真值表（adapter 常量钉出处），表外保持
  派生兜底；UI 默认与 fixtures 同步真实值。
- **#118 / PR #120**（狗食 Bug2）：node 重启遇孤儿 Runtime 必崩——cli.ts 的
  `let sessionSend` 声明晚于使用它的 RunManager 构造与 recoverOrphans 调用，
  孤儿+命令 spool 双命中时 TDZ ReferenceError。修法：声明前移 + 真子进程
  CLI 级回归（spawn 真 cli 组合根、双种子驱动 send 路径）。
- **#119 / PR #122**（狗食 Bug3）：reconciler 的 nodeLostRun 臂（「心跳新鲜但
  未列出该 Run → lost」）对刚创建的 Run 是必中竞态——节点要等下一个 10s
  心跳才有机会列出新 Run，真模型长生命周期 Run 三跑三判 lost（最速 +353ms），
  账本已死、runtime 还在跑（僵尸 Run）。修法：新生儿宽限（Run 年龄超过
  DEVICE_LEASE_MS 才允许该臂定罪）+ Run 出生时间改由领域时钟显式写入。
- **PR #121 复审追加**：`node cli secret set <provider> <slot>` 的 main() 层
  positional 解析序与 usage/权威规格相反，照文档敲必 EXIT=2 不落盘（此前
  main() 层 argv 零测试覆盖）。修法：实现对齐规格 + 真子进程 argv 回归
  （含「正序唯一」负例，防兼容垫片静默放行）。
