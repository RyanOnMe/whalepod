# ADR-0030：项目新工作发现与预授权立项

- 状态：已采纳（Accepted，2026-11-09）。尚未实现或验收；三个切片按各自门槛推进。
- 决策记录：维护者同意用责任人预确认的模板派生仅供私有草稿执行的首份约定，以及试点人工建 Task 必须标记是否占用交付槽位。两位独立 Agent 已复核事实与槽位裁决、跨 Task 输入、撤权、费用及私有投影。
- 承接：[Router 与 Executor 持续协作方案](../agent/2026-11-02-router-executor-autonomous-dispatch-plan.md) §8 的 RD-04。[已有证据](../agent/router-real-model-quality-acceptance.md)覆盖 M1R-A 生产装配、既有工作 Router v4 的真实模型与人工复核，以及 v5 工程回放；不作为新工作发现、立项或 M1R-B 的验收。
- 关系：[ADR-0028](./0028-continuous-work-and-autonomous-dispatch.md) 只允许续接既有 Task，保留原授权边界；本提案为 RD-04 增加独立的立项入口。[ADR-0026](./0026-project-coordination-lifecycle-and-cost.md) 的隔离与结算、[ADR-0017](./0017-task-agreement-and-handoff-boundary.md) 的任务约定、[ADR-0025](./0025-source-revisions-and-project-understanding.md) 的事实边界、[ADR-0027](./0027-run-project-context-snapshot-and-consumption.md) 的输入快照继续适用。

## 问题

场地工作已经有人承接，可以把新的无障碍座席要求送入已有工作。另一位成员在同一项目的日常筹备讨论中报告了已核实的接驳困难，项目内却没有相应的交付工作。现在的 Router 必须绑定已有 Task、Work 和 Mandate，不能用临时 Task 或空 `workKey` 表示这个缺口。模型也不能把一条讨论当成委派、任务约定或发布许可。

RD-04 需要把三个动作分开：发现一个有证据的新缺口；依据人已给出的立项许可把它变成有人负责的 Task；由既有派工端口复核后生成私有草稿。发现是否准确、是否有立项权限、当前能否执行分别取证。

## 决定

### 1. 首个范围：一个项目内，一项可明确区分的草稿交付

- 首个切片使用 WhalePod 现有普通 Task 评论入口。团队一次性选定项目内已有的筹备讨论 Task，成员照常留言；这条消息可以是新工作的出处，但新工作的 **目标 Task 和 Work 尚不存在**。不要求成员手建目标 Task、复述材料、发执行提示词或 `@Agent`。没有项目级讨论入口，不创建占位 Task，也不把此切片解释成已接通无 Task 的项目消息或外部办公来源。
- 先执行 ADR-0028 的程序准入。首个试点只从**没有现行 Work、没有有效订阅**的指定筹备讨论 Task 接收发现来源。入口已有 Work 时走既有路径：有效订阅直达，否则由 Router 或原等待/拒绝守卫处理；等待中的 Work 不算无 Work。Hub 在生产评论事务内按事件和来源版本记录唯一归属（含关闭、拒绝），与入口 Work/订阅变更共用事务围栏；重放读取原决定，不改路。入口状态变化后旧评估失效，不以旧事件补发另一入口。场地 Task 接收原工作的补充，筹备讨论 Task 发现接驳缺口。发现评估识别出混合需求时交人判定；已送入既有工作路径的消息可按原退回流程指出独立缺口，首切片不自动拆分或补发第二次评估。
- 首个试点只开放一个预先登记的交付槽位，例如「本次活动的无障碍接驳备选草稿」。槽位独立于原场地方案，具有明确的成果、责任人与验收条件；消息中出现新名词、已有工作暂时未完成、状态变化或负责人相同，都不足以创建新任务。活动范围和交付槽位在一次授权时登记，不按消息、词语或规则逐条设置。
- 只读同项目、当前允许读且已适用于整个项目受众和获准协调模型的评论、约定及已发布成果；受众或模型处理权限未知则排除并标记目录缺口。项目可见的 Task 标题和描述只取获准公开的模板和活动标识。评论及其引用、候选理由、目录省略原因留在责任人的授权读面，状态日志仅含不透明 ID、版本和固定原因码；不进入通用投影、通知或团队事件。来源撤回后同步拒绝候选正文，缓存和评估副本沿 ADR-0026 的隔离与留存规则清理。首切片不读取其他成员的私有成果、会话、Workspace 或凭据；不能以协调职责扩大受众。

### 2. 发现候选不是立项许可

- 为受限协调计算增加独立用途 `discovery`。它绑定项目、立项许可版本、责任主体和来源清单，不绑定不存在的目标 Task/Work；不复用现有 Router 的 `dispatch` 提案，也不伪造 Inference。继续复用受限 Node/Runtime、隔离的协调凭据、无工具、清单读取回执、结果租约和 Project 单飞。推断、既有工作路由与发现共享 Project/Team 额度和执行单飞，不因用途增加并发或预算。
- 清单冻结当前来源的身份、版本、digest、授权代次、出处、纠正水位，已登记槽位、当前可读工作及成果目录、覆盖范围与省略项，以及许可、模板、配置、规则和提示版本。Router 只能引用清单中的条目；输出不含可生效的 Task/Work/主体 ID、权限、发布命令或预算。Hub 核验引用和读取回执，不能把格式正确当成语义正确。用途独立登记能力和输出契约，旧 Node/Runtime 不领用此类任务；接受前验证用途、唯一活跃尝试及租约，拒绝跨用途、旧尝试或清单不匹配的回执。Project 单飞和额度以全部用途共享的事务检查为准。
- 对每个来源区分：①与已有工作对应或已被可核验成果覆盖；②有证据的独立缺口；③信息不足或冲突；④无关、假设或普通进展。第二类须引用当前的具体要求或经核实的直接观察，指出其对应的已登记交付槽位及原工作未涵盖的理由。消息作者和版本可验证，只证明「谁报告了什么」；引述指令、声称已审批、来源中的角色自称都不是授权，也不能升级成业务 Decision。没有读到依据、目录不完整、可能存在不可读的覆盖工作，均不得解释为「没有对应工作」。
- **事实门**：立项许可登记可核实此槽位事实的具名成员。自动立项要求当前普通讨论版本包含直接观察并引用独立佐证，或取得独立核实回执。佐证仅限同项目由预先登记的核实人正式发布的当前版本；核实回执须由该核实人经专门入口确认确切评论。两个入口均要求核实人与评论作者不同，排除自行发布材料再自引。Hub 核对权限、身份、固定引用或回执、来源 ID、digest、槽位和许可代次。是否确实支持缺口仍由语义评估判定；直接观察无佐证、来源矛盾或拿不准时只保留候选。转述、假设、冒名或评论内的「已批准」不足以自动立项。
- **槽位门**：Hub 从项目、已登记活动和模板槽位生成稳定身份。空行表示未核对，不能代表没有对应工作。责任人在启用自动档前核对完整的项目任务及成果目录，记录其代次与每项是否覆盖槽位。只有当前代次已核对且无占用才是 `eligible_empty`；不可读、未分类、扫描被截断或有冲突均为 `unverified`；已有承担、已完成或曾占用该槽位均不自动再开。新版本或候选只能提出理由，不能把槽位标为空。
- 自动档启用时，可能改变覆盖的人工入口与自动立项共用 Project 锁及槽位唯一约束。人工创建须明确认领该槽位或提交「与槽位无关」的分类建议；认领已有槽位时返回现有任务或冲突，不再创建。未由具名槽位责任人核对的新任务（包括 pending 指派和交接新建）、改派、范围变更或成果发布，推进目录代次并令旧核对失效；普通创建者的建议不能维持 `eligible_empty`。未分类的旧客户端请求必须显式先退出自动档才可照常提交。关闭自动档后保留人工路径和占用记录，恢复须重新核对；接不上任一写入入口则仅开放影子发现。模型不以标题、相似度或可见子集绕开此门。
- 记录分开：来源事件身份用于去重；`discoveryEvaluationId` 和评估摘要用于冻结输入与判定迟到结果；槽位身份用于并发立项；候选版本用于保留证据变化。候选可被采纳、拒绝、替代或过期；候选列表不承担 Task 状态机。系统生成的普通进展、候选、Run 终态和草稿不回流成新立项触发；无变化不轮询模型。

### 3. 一次授权，分开授予立项和执行

- 项目 `off` 为默认。Team Owner/Admin 显式开启发现并设置项目范围与费用上限；现有 `project.createdBy` 不授予新权限。具名的未来 Task 真人责任人另行确认一份项目立项许可，绑定本人、可见入口、活动与交付槽位、模板版本、项目、资源范围、允许的草稿动作、时限和总额度。协调设备操作者与费用承担者仍按 ADR-0026 独立确认；Owner/Admin 不能代另一成员接任任务或开放其设备、凭据和资源。
- 许可明确区分「仅发现」「可自动立项」「可自动运行私有草稿」三个档位。无本人接任授权，不自动建已承接任务；无执行授权，不创建基于此许可的 Run。运行档位必须同时具备立项授权，也可被单独关闭。首切片限定责任人本人、本人授权现场和本人为私有草稿受众，不自动指派给其他成员。父代次、缩权关系和执行拒绝条件随子 Work/Mandate 的续期、暂停或恢复保留；批准某个 Router 意图不能替代另行授予执行权限。
- 候选不清楚事实时，在责任人的私有读面标出可验证的阻塞原因和期限，影子档不自动提问或通知。立项范围、任务责任、费用分别由原授权人裁决；进入自动档后才允许给指定且有权读出处的核实人生成去重核实请求，回答绑定主体、槽位、确切来源版本和许可代次。回答或评论内的「同意」不扩权；新权限须经原授权入口确认。普通噪声、重复事件和已过期候选不提问。

### 4. 从候选到真实 Task：锁定批准过的约定

- 采用**本人事先确认的具体约定模板**。责任人确认时即冻结目标、约束、验收条件和待确认问题的模板版本；首切片只允许 Hub 填入已登记活动身份和经过验证的来源引用。模型不生成验收条件，不补填开放字段，不添加权限；模型摘要是候选解释，不能当作 Task 约定或 Run 执行依据。
- 对 ADR-0017 增加一条窄规则：只有经 §3 和本节许可的立项，才允许固化 `origin=preauthorized_template` 的首份 TaskSpecRevision，**仅允许 RD-04 草稿派工按当前父许可绑定**。普通 Run、重跑/续跑、交接、正式审阅、发布和验收均不得以它充当真人已确认版本；责任人须经既有确认入口生成新的正式版本。约定保持开启，正式 resolver 不读取该派生版本，不走 ADR-0025 的成员确认 Decision 投影。发现事实也不写入 Decision。
- 持久化区分三件事：Hub 物化 Task 与约定的系统来源和时间；具名成员预确认具体模板和预接受责任的真实回执；子 Mandate 继承的父许可。`createdBy`、指派接受和约定确认必须能表达这些不同来源，使用可区分的持久化身份与完整约束，不填虚假真人 ID、`acceptedAt` 或 `confirmedBy/At`，也不借用「给 Agent 指派即接受」。约定引用放入受限输入，不公开投影。自动档未达到实施与验收门槛时，只走已验证的影子发现及常规人工立项/确认。
- 模型接受与业务应用分两次裁决。Hub 接受结果时复核评估、尝试、租约、实际读取与清单版本；应用时以评估 ID 幂等，在 PostgreSQL 事务中锁定许可和交付槽位，按固定锁序复核当前成员、项目状态、许可、模板、槽位、目录水位、来源纠正和授权，以及适用额度。还要和同一槽位的人工立项竞争：该槽位的自动入口与人工认领/创建入口使用同一约束；不具备共同约束或目录水位变更时不提交，先重评。源事件重放、两个成员同时报告、结果迟到或进程崩溃均不能产生第二个立项。
- 通过后，在同一事务以系统 actor、所代表的真实责任人和可查的预授权回执建立一个已承接的 Task、一份约定、一份 Work 和受源版本约束的收件箱项。仅运行档创建可执行的子 Mandate 与待派工记录；它只能缩小父许可的资源、动作、受众、工具、时限与额度。仅立项档无可执行子 Mandate、无待派工，Work 的所有派工入口都拒绝基于此许可运行（`autoDispatch='off'` 本身仍允许人工批准意图，不足以表达拒绝）。事务不等待模型或 Node，不产生部分有效立项。
- 筹备讨论 Task 与新 Task 不同，通用 `task_message` 入箱仍拒绝跨 Task。RD-04 使用专用、仅 Hub 物化的来源绑定，固定入口 Task、确切评论和所采用的佐证/核实回执版本及 digest、项目与授权代次、获准候选与父许可、目标 Task/Work 和责任人。入箱、快照冻结、派发、读取、模型调用和候选登记复核同一绑定及全部依据的当前权限、有效性、纠正水位和核实人资格；其中任一项失效都使绑定失效。客户端不能提交或修改它，其他 Work、Run、旧设备或普通跨 Task 读面不能使用。读取回执核验版本和实际消费；版本失效不静默换新。

### 5. 私有草稿沿原执行边界

- 自动运行必须在立项提交之后进入既有 Hub 派工端口与 RunOrchestrator。检查当前 Task/约定、父许可、子 Mandate、来源权限、额度与 Agent/现场是否合格；只有全部通过才冻结输入并派发。机器 Run 使用 ADR-0028 的固定草稿工具面和 `approval_required`，不开放 `full_access`。Run 创建即标记私有输出；Node 仅发固定项目状态，Hub 在落投影前按持久标记拒绝其余项目事件。结束摘要、工具结果、错误内容、候选标题/正文、派生预览不得进入团队 HTTP/WS 实时或历史、交接、项目事实或 Router 输入。草稿只供责任人读取，确认正式约定不会将旧草稿变为正式候选；需绑定正式约定另走常规执行及人工发布、验收入口。
- 协调模型的来源许可不转给 Executor。派工时冻结获准的实际执行模型接收方（服务商、模型、端点、账户、用途与授权代次）；逐项来源及其佐证都必须明确允许此接收方。每次出站在受控出口复核相同绑定与现态权限；未知、变更或仅批准协调模型时，不发送正文，不回落到现场默认模型。
- 发现评估的实际费用由原项目协调账本结算；子工作不得接管既有未绑定费用。父许可分别限制累计派发数、模型调用数、token 和费用。每次实际模型调用（含后续轮次、重试）都必须在出口前按调用身份预留最坏上界，事务同时检查适用的 Team、Project、父许可及子 Work；同一出站尝试只结算一次，不确定是否发送的尝试保留预留直至对账。只启用能强制限制输入/输出上界、禁止未授权直连或 SDK 隐式重试的模型路径；不能证明上界或拦住每次请求则保持自动运行关闭，不把现有每 Run 一次预留算成硬上限。仅立项档不预留 Executor 用量。重新创建候选、换 Agent 或更新许可不重置累计限额。超预留的可信实耗仍如实入账并停止后续调用；缺失才按既定兜底结算。
- 许可/来源撤回、过期、换版、项目关闭或责任人退出时，停止新应用和新派发，取消未投递的机器工作意图；新许可不恢复旧评估、子 Mandate 或派工。启用自动档前需有生产纠正/撤回路径：原作者可提交版本化更正或撤回发现依据，Hub 推进来源水位并失效旧绑定，不以测试直接改库代替。派发后复用 ADR-0027/0028 的记账语义；真送达、下载、专用读取、工具调用、模型出口和候选登记都在线核对绑定及父子许可代次，断线或仅有旧本地副本时拒绝。必须证明下载后首次读取前撤权仍能阻断，且更换、续期子 Mandate 不能绕开。已准入的在途请求按有界中止/对账处理，已交付字节只清理和阻止后续使用；不自动换 Agent 重放，不改活跃 Run 的原快照，也不复活终态。已成立的 Task 留给真人处理。

## 交付与验收

| 切片 | 交付 | 退出判据 |
|---|---|---|
| RD-04a 影子发现 | 默认关闭；启用后只记录项目候选及出处，受限读面向许可责任人展示。 | 真实评论触发有界评估并保存可核验的新缺口；已知快路径照常直达；任何候选均无自动通知、提问、Task、约定、Work、派工或 Run 写入。可在后续切片沿人工入口处理候选。 |
| RD-04b 授权立项 | 实现 ADR-0017 的窄规则；接通事实/槽位裁决和生产来源纠正；建立可追溯 Task、约定和 Work。 | 机器并发、人工/机器两种提交顺序与交接新建只形成一个槽位占用；撤权、冲突、目录变更、费用不足或关闭无新增；派生约定不会被当成正式确认；仅立项档即使批准普通 Router 意图也无 Run、Executor 预留或调用。 |
| RD-04c 私有草稿 | 接通专用来源绑定、在线读门、调用级费用守卫和私有投影后，经真实派工与 Runtime 执行。 | 无人工建目标 Task、`@Agent`、额外指令或上下文搬运：新缺口实际产生一个 Run，读取并消费确切的跨 Task 来源版本；第二名已登录成员读公开对照证据为 200、读草稿为 404。把草稿标记放进候选标题、模型最终答复和工具错误，HTTP/WS 实时和回放也无该标记。无自动发布。 |

- **正向组合**：A 的无障碍座席补充续接原场地工作，订阅入口不启动 Router；B 在筹备讨论中报告独立接驳困难并引用已发布的勘察材料，Router 读取当前可读项目依据，独立候选进入授权立项并产出私有草稿。已有工作未被重新创建、误投或重开。RD-04c 完成才有资格进入 RD-05 的组合验收。
- **必做负控**：已覆盖/已有承接、无关进展、假设、假冒审批和跨项目或私有输入均无自动立项；同一事件不同时触发两类协调评估；进入发现的混合消息保留待人工判定的独立要求，既有工作路径已送达的消息可带原因退回。重复、乱序、更正、两人同时报告、与人工立项竞争、结果迟到、应用和派发前的撤权、评论不变而佐证撤回、预算耗尽、离线恢复、未知副作用、不合格 Executor 和越权工具均留可判定结果。来源只允许协调模型 A、不允许执行模型 B 时，A 可评估、B 的受控出口无模型请求。相同槽位不重复建任务或派发，同一 provider 请求不重复收费，真正取舍只由正确主体收到一次问题。
- **证据拆开**：工程沿生产 HTTP/WS、PostgreSQL、Node/Runtime 和独立判定取证。关联准入、清单、读取、候选、许可、立项事务、派工、实际消费和草稿下载；缺一环即失败。自动档启用前，目标装配、真实模型和提示版本须独立通过 RD-04 冻结保留集及人工复核：正向独立缺口能发现，已有承接、材料不全、注入、混合来源均无错误自动立项，且引用齐全。任一错误自动立项或切换未验证的模型/提示即退回影子档，既有工作 Router 的分数不能替代。真人是否减少提示词、搬运与打扰另在 RD-05 验证。真实外部来源、无 Task 项目入口、跨成员草稿委托和同一 Run 的动态注入不计入本提案。

## 实施顺序

本 ADR 合入后登记实施 Issue，优先推进 RD-04a（影子发现和独立质量验收），随后是 RD-04b（事实/槽位/预授权立项）和 RD-04c（专用跨 Task 读取、费用守卫和私有草稿）。任一部署或产品验收门槛缺证据，停在对应已验档位。自动拆分混合消息、跨项目和外部来源另议。
