# ADR-0022：交付物依据是历史绑定的只读投影

- 状态：实施中（#440；用户已批准交付闭环与成果依据概览范围）
- 日期：2026-10-26

## 决定

依据围绕准确 Artifact 身份构建：先按现有文件权限重新判定，再从来源 Run 的不可变绑定读取历史已确认约定、同任务固定输入与上游固定文件输入。历史 NULL 不能冒充确认空清单；当前不可见或摘要不符的材料不下发，明确清单不完整。对约定与输入从不查询任务当前最新版本。

关联说明只取同 Task、同来源 Run，且发布系统块同时具有准确 sourceRunId 与已发布 artifactId/sha256 的最近一条交接版本。不查询私有草稿，不把同 Run 全部产物或其他交接当作当前文件的验证记录。公开叙述的文件引用再次筛除当前非发布/不可读项；不泄露其身份或数量。

投影只证明记录存在与版本关系。模型文字默认待核实，发布者标记仅表示其人工核实；没有记录不代表检查未做，工具成功不代表该成果正确或检查充分。原始工具正文、设备路径、凭据与 owner-only 文本不进入新读面。

HTTP 只新增 `GET /artifacts/:artifactId/delivery-basis`，复用 Session 及不可见 404 规则；不写表、不启动执行、不增加角色或验证状态机。Web 独立面板校验文件/任务身份，失败明确重试，不把失败渲染成无依据。

## 验证

协议/匹配负控、实际 HTTP 配对与协议帧驱动的历史约定和材料投影、私有候选 404、准确 Run 与摘要、Web 失败重试与不发命令。验收与剩余边界登记 delivery-basis-acceptance。
