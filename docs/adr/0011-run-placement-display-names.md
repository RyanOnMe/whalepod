# ADR-0011：运行落点显示名进团队投影（#211 B1）

日期：2026-09-18
状态：已接受（随 #219 合入）

## 背景

原型运行卡有"设备 / 工作区"，但团队投影刻意剥离 `deviceId`/`workspaceId`
（`task/view.ts`，02 Step 1）。执行区无法回答"这次跑在哪台机器上"。

## 决定

**B1：只给显示名、不给 id，所有人可见。**

- `TaskRoomRun += deviceName / workspaceName`（可空），id 类内部标识仍不出投影；
- 名随任务走：任何能 `GET /tasks/:id` 的成员都能看到（含被授权成员——他以前在
  设备页看不到责任人的设备名，这是**新的信息披露**，见下）；
- 落点是**当前名、不是快照**（JOIN 语义；Run 不是审计账本）。

## 为什么是 B1（而不是 A / B2 / C）

- A（维持剥离）：零改动，但"跑哪儿了"是协作要回答的问题，排障时换页查；
- B2（按人分叉读模型）：为"少显示一个名"付双倍复杂度，不值；
- C（给 id）：与剥离口径直接冲突，不考虑；
- 名不是凭据：看得到名干不了任何事（配对/撤销走设备页权限，id 未暴露）。

## 诚实记录（评审 O1）：这是新的信息披露

`GET /devices` 只回本人设备——PR 前被授权成员在设备页看不到责任人设备名；
PR 后他能在任务房间看到。设备名用户自起，可含定位信息（"家里那台"）。
02 Step 1 原文只剥离 Token/path/session 类凭据，显示名不在清单内，故与 B1 自洽——
但"设备名团队可见"是一条**使用忠告**：别起敏感名。本条即留痕。

## 02 Step 1 口径收窄

"剥离 id 类内部标识，显示名随任务走"——替代原来的"设备/工作区信息不出投影"。
`dshSessionId` / digest 类仍剥离（`task.integration.spec.ts` 的脱敏断言看着）。
