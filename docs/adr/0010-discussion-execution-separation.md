# 0010 讨论与执行分栏：评论区只承载人际交流，指令与运行独立成区

ADR-0009 的 **O3-a** 把「讨论 + 指令 + Run」合并进同一条线程，用「显式 `@Agent` 开头才是指令」来区分两种发言。产品评审（2026-09-11，用户当场否决）指出这带来的状态混乱不可接受：**评论区应当单纯是人与人之间的交流**。本决策取代 O3-a（以及 0009 决策 8 里「指令即线程消息、合并展示」的那部分），其余决策（审计链、受理落账、并发语义、Agent 可指派、审批档位）全部保留。

## 背景：混乱是结构性的，不是视觉问题

`task_message` 一张表、一条流里混着两种**命运完全不同**的东西（`03` §2.2 的 `kind`）：

| | 讨论消息（`kind=discussion`） | 指令消息（`kind=instruction` / `followup`） |
|---|---|---|
| 送达语义 | 落了就算送达 | 可能 `pending` / `accepted` / **`rejected`**（理由取决于 Run 是否存在、是否 `running`） |
| 前置权限 | 无（是成员就能说） | 需要指令权（④ `task_instruction_grant`；今天只有责任人） |
| 副作用 | 无 | 建 Run、或改变正在跑的 Run |
| 界面 | 一条气泡 | 气泡 + 状态徽标 + 牵引出的运行卡与实时输出 |

后果：**「我这句话被 Agent 拒了」与「我的讨论没发出去」在界面上长得一样**；运行卡插在讨论流里打断对话；同一个输入框承载两套权限与两套失败语义。视觉分隔（泳道、折叠）只能减轻，不能消除根因——根因是「同一列里两种命运」。

## 决策

1. **评论区纯人际（读模型隔离，不是 UI 自觉）**：任务视图的讨论流**只返回 `kind='discussion'`**。这是一条**读模型**约束，由机器判据钉住（即使库里存在指令消息，讨论流也不得出现它们）——不靠前端过滤，否则哪天前端忘了过滤，混乱就回来了。

2. **执行独立成区（任务页并列两栏）**：讨论（左）与执行（右）并列，一眼分清「人在说」与「Agent 在干」。执行区承载：**指令输入框**、**指令列表与状态**（`pending` / `accepted` / `rejected` + 理由）、**运行列表**、以及已定型的 **Run Console 卡内覆盖层**（ADR-0008 的 L3 运行视图，切片⑥）。「接着说」（followup）也在执行区，不再表现为"在评论区 @Agent"。

3. **存储仍共表（`task_message`），审计链不变**：指令继续写进 `task_message`（带 `kind` / `origin` / `instruction_state` / `run_id`），因为 ADR-0009 决策 2 要求「谁在什么时候让 Agent 干了什么」可追。合并的是**账本**，不是**界面**——两者被读模型切开。拆出独立 `run_instruction` 表能更纯，但要迁移 `instruction_state` 与 `dispatch_outbox.message_id` 映射，收益不抵代价（用户 2026-09-11 选择「保留共表 + 读模型隔离」）。

4. **`@Agent` 不再是评论区的语法**：讨论输入框里 `@` 只用于**提到人**（与今天的成员提及一致）。指令是执行区的动作，不需要靠文本前缀解析语义——这同时去掉了「同一句话是讨论还是指令」的解析歧义。

5. **审批档位不做「自动触发降级」**（用户 2026-09-11 选择）：ADR-0009 决策 5 提到的「自动触发的 Run 强制降级为需审批」**不再实施**。切片③c-2（由指令起 Run）与切片⑧（`approval_policy`）都按同一档位解析规则走：Agent Revision 默认 → Task 覆盖（`NULL` = 继承）→ 建 Run 时解析成具体档位写 `runs.approval_policy`。触发方式（人点 / 指令自动）不影响档位。

## 影响

- **切片③c-1（已合入，PR #193）不受影响**：它改的是「指令何时下发」的状态语义，与展示无关（决策 2/3/5 都保留）。
- **切片③c-2**（无活跃 Run 时按指令起 Run）入口改为**执行区**；`runs.trigger_message_id` 仍指向那条指令消息（审计链不变）。
- **切片④ 授权**：讨论不需要授权，授权只作用于执行区的指令——授权模型反而更清晰（授权 = 能不能驱动 Agent）。
- **切片⑥ UI**：形态从「合并线程 + @Agent」改为**任务页并列两栏**；`prototype/task-room-conversational.html` 需要按本决策重画（它现在是合并线程形态）。
- **公开命名**：API 里的 `comments` 现在**语义上就是"人际评论"**，与分栏后的含义一致，故保留；`comment.created` → `message.created` 这类统一改名放到切片⑥（那时本来就重写这批文件），单独立账避免半成品改名。

## 未决

- 执行区是否需要「有人发起了执行」这类**最小系统提示**出现在讨论流里（用户倾向不加；本决策先按"不加"实施，若实际使用中发现信息真空再单独立项）。
- 讨论流是否要给「被拒绝的指令」一个**跳转入口**（目前只在执行区可见）。
