# ADR-0013 显式执行意图与统一执行入口

状态：已接受产品方向（2026-10-14 用户批准操作优化计划），实现待 P1-315 评审。

## 问题

主要输入入口无法独立选择首次执行 Agent；同一段草稿在后台 Run 结束后可能从追问变成新会话。用户选择的接收者、会话来源与版本需要成为提交意图，不仅是一段提示文案。

## 决策

1. Task Room 执行栏统一承载首次启动、追问、显式新执行和续跑。讨论不驱动 Agent、权限页独立、真人责任、单活跃 Run 和终态不复活保持。
2. HTTP 指令请求增加可选 `intent`：new；followup + runId；resume + runId。旧 API 客户端与 Agent 指派自动驱动缺省时维持既有自动路由；Web 的主要入口始终明确意图。
3. new 请求带显式 Agent/Revision；不得降级为现有 Run 的追问。followup 钉来源 Run，来源不再是当前活跃执行则冲突/拒收，不建新 Run、不改投另一 Run。resume 引用同 Task 终态来源，使用来源 Agent/Revision/Device/Workspace，复用既有同现场/会话守卫，并产生新 Run 血缘。
4. 运行状态在编辑/确认期间变化时，保留草稿并要求重新选择。服务端再判权、判状态和唯一活跃，前端不是安全边界。失败重试同意图使用同 key，改变意图或正文产生新 key。
5. 初次/新执行可以按既有规则解析责任人现场；授权成员不能浏览其私有 Workspace 清单。UI 明确自动选择，显式选择仍过归属/可用性守卫。
6. 活跃追问沿用当前 Run 档位，续跑采用来源 Revision 与当前 Task 覆盖解析审批档；界面展示并继续执行既有完全权限确认。Agent 指派即驱动与授权保留规则不在本 ADR 修改。

## 影响与验证

不改 Node/Runtime wire 或 DSH 版本。新增 HTTP 兼容字段、Hub 守卫及页面模式。验证首次执行、活跃追问、排队、状态竞争不改投、同现场续跑/来源版本、拒绝/越权/幂等；复跑登记在统一执行验收中。此 PR 涉及协议与控制策略，至少两人 review 后合入。
