# ADR-0015：撤销指令权与尚未派发的追问

- 状态：拟实施，安全控制合入前需独立评审
- 日期：2026-10-14
- Issue：#321

## 决定

撤销后新请求拒绝，旧页面保留草稿但不能发送。尚未入Outbox、或已入run.followup Outbox但attempt_count仍为0的追问，在撤销事务里settle rejected(FORBIDDEN)并追加现有comment.created状态事件，不永久pending。已开始任意派发尝试（attempt_count>0）的命令可能已抵达Node，保留真实回执；不因缺ack而伪造“已撤回”。

撤销按Task→活跃Run→该追问Outbox→消息顺序串行化。先取得活跃Run锁，再删授权和结算，避免与进入running的补发竞争。Outbox未尝试条件在行锁内重读，worker若先claim则已进入无法保证撤回的边界；worker不持Run锁，followup ack也不持Run锁，因此不新增反向锁环。

补发器在生产running迁移事务内再查作者当前指令权与成员启用状态，失效则明确拒绝并发事件。Run/审批操作仍按独立权限，撤销不自动取消已创建Run、不改变初始run.start；用户需要停止整次执行时使用现有取消。进入Runtime的指令可能有副作用，不能重写既成事实。

进行中责任交接维持现有禁止改派的规则：先结束/取消活跃Run；改派后新成员接受，授权名单保留；历史会话/候选拥有者不转移。改变这些规则需另起ADR，本批不静默清名单或接管私有会话。

## 验证

真人HTTP授予/发送/撤销及成员停用，协议帧驱动Run；真实PG证明撤销先完成无派发、未尝试命令失败、已派发迟到ack仍真实settle，合法作者正常补发、重试无复活。页面授权变动保留草稿。固定锁序与worker claim窗口须留确定性并发判据；UI与安全门随实现交付。
