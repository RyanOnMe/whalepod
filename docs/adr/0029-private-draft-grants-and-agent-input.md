# ADR-0029：跨成员草稿授权与 Agent 中间产物交付

- 状态：已采纳（Accepted，2026-11-09）。尚未实现或验收；两阶段分别交付和启用。
- 日期：2026-11-09
- 决策记录：2026-11-09，维护者确认先交付指定成员按件阅稿，再独立验证 Agent 单次使用。独立 Agent 已复核来源证明、再交付权限、模型出口、撤权和派生隔离。
- 承接：[ADR-0028](./0028-continuous-work-and-autonomous-dispatch.md) §6、§7、§9 与 §16 的 RD-03c3 待决项；具体实现按评审后的切片另行登记 Issue。

## 问题

既有任务的机器 Run 可以生成 Artifact 候选，责任人能够读取、审阅并决定是否发布。现在若只想让另一位成员看某份草稿，或让另一个 Agent 拿这份草稿继续工作，没有比复制文件或正式发布更窄的产品路径。把接收人写入 Mandate、加入团队或送达通知，均不足以说明「谁能看哪版草稿」「能否交给模型」或「谁负责下一次执行」。

需要让一件草稿有可追溯、可撤销的接收路径，同时保留原 Run 的责任人、私有 Workspace、模型凭据和正式发布规则。

## 决定

### 1. 先开放指定成员阅读，再开放一次明确的 Agent 使用

| 切片 | 路径 | 边界 |
|---|---|---|
| RD-03c3a 指定成员阅稿 | A 在已正常完成的机器 Run 的候选中选择一件，核对正文，明确指定当前团队成员 B 和到期时间；B 用自己的会话接受后可读取固定字节 | 不创建 Run，不进入任何模型清单，不新增候选编辑、团队批注、转授权或正式发布权 |
| RD-03c3b Agent 中间产物 | A 另行确认「允许 B 阅读这一版材料，并用于指定 Task、Agent 和模型的一次 Run」；B 接受该授权，在自己的合格受管现场，经 Run 创建入口明确发起 | 同项目、处于 `in_progress` 的既有 Task、责任人已接受指派；评审中或终态 Task 拒绝，不改变原状态。限定一个接收 Run、一跳交付。模型出口或隔离未验清时只开放 c3a |

A 必须同时是原 Artifact 的拥有者、来源机器 Run 的真人责任人及来源 Task 的当前责任人，且仍是启用中的成员。B 以 WhalePod 内不可变的成员身份绑定；角色、项目成员资格、显示名、讨论 @、Agent ID、通知或持有链接都不授予读取权。管理员可用既有成员停用等管理措施止损，不能据此读取、替 B 接受或代 A 授权。机器 Run 的 `principalUserId = onBehalfOfUserId = humanOwnerUserId` 不变，草稿的拥有者与正式发布人不转给 B。

跨成员 Agent 使用发生在 B 自己负责的既有 Task，执行现场与费用由 B 明确授权，不取得 A 的指令、审批、设备、凭据或费用授权。绑定 B 的 Device/Workspace 只用于授权和调度；私有 Runtime 不挂载常用 Workspace，也不接收 B 的通用模型密钥。同一成员的两个 Agent 也要分别确认授权与使用，人的读权限不传给任意 Agent。同一 Task 仍只允许一个活跃 Run；不向已有 Run 注入或沿用旧会话。

### 2. 授权记录与版本

新增独立的 `draft_share_grant`。它固定 `grantId`、授权人与接收人、Project、来源 Task/Work/Run、Artifact ID/sha256/byteSize、来源 Run 与授权时当前 Mandate 的版本、来源权限清单及代次、用途与到期时间。Agent 用途额外固定目标 Task、Agent Profile Revision、模型用途和受控出口身份（实际服务商、模型、端点、授权账户及策略版本）；执行时再固化实际 Device/Workspace 与现场授权代次。Grant 不携带正文、凭据、本机路径或可绕过服务端判权的链接。

- 仅可选已上传并通过字节校验、未发布、并非 c3b 密封派生件的候选。来源必须是新增的受管机器 Run 档：创建时固定许可和全部可接触内容的清单（含指令、约定、工作输入、工具结果与可验证上游），在首次读取或发模型请求前约束 A 的工具和实际模型出口。无旧会话、任意 Workspace 读取、外部连接器、未登记工具或来源不明的自由文本。采集只认该 Run 在独立、初始为空的输出根新写并带 Run 回执的文件；拒绝旧工作区文件、外部链接和普通上传口补录。Run 正常结束且证明闭合才可授权；A 自行核对不能补齐证明，普通/历史 Run 不回填。
- 每件来源的当前规则必须明确允许向 B 交付相应派生材料。c3b 还须明确允许交给所列模型、端点、账户与用途；A 本人能读、B 在团队中、正式材料可读或来源曾用于另一个模型，都不能推出此权限。首切片只接受 A 有权自行授权且已登记的材料，或拥有明确再交付/模型用途策略的可验证项目材料；权限未知或无相应策略就拒绝该用途。A 核对固定版本并确认受众和用途，不能覆盖系统拒绝。输入、上游权限或模型策略代次变化即使以后恢复，也不复活旧 grant。
- 状态为 `offered → active`（B 接受）或 `offered → declined`（B 拒绝）；`offered/active` 均可进入 `revoked/expired/superseded`，其余状态均为终态。提议期间 B 在授权读面只见最小邀请信息，该读面不新增标题、正文、来源 Run 或其他候选。原投影已可见的普通候选元数据不因邀请而消失，也不含邀请关联。到期不得晚于当前 Mandate 及任何输入授权的最早到期，读时按 Hub 时钟直接判定，无须等待清理。以新的 grant 身份/代次重授，不恢复旧 grant、旧接受回执或旧 Run。
- 每对 Artifact 版本与接收人最多一份未终结的 grant；扩大用途、换接收人、换目标 Task/Agent Revision 或换字节都要重新明确确认。替代可同事务失效旧 grant 并建立新提议，旧链接不随同名文件或新版本迁移。重复接受、撤销或消费用 actor/对象/版本和请求摘要做幂等校验，拒绝跨主体或跨资源重放。
- 同步校验当前成员状态、Project、当前 Task 责任人、Work/Mandate、Artifact 状态与固定摘要、可验证的来源权限。权限未知视为不可读；历史回执、已经看过、曾经持有有效授权不能当作当前资格。
- c3a 与 c3b 都保留 `draftRecipientUserId` 的现有校验，只能是原责任人。逐件授权让 A 能先看生成内容再选择受众。若实际使用证明需要「以后符合条件的草稿默认送 B」，另行评审显式、版本化的 Mandate 受众指定：A 确认受众、用途、可用依据和上限，固定到生成 Run；合格产物达到可交付状态时，Hub 在同事务按已确认版本、当前权限、产物摘要和接收人幂等生成该件的有界 grant。没有新确认、版本漂移或产物资格不明时不生成。仍需 B 接受，不自动获得模型使用权，不补发历史件。此草案不放开该字段或实施默认送达。

### 3. 读取、Agent 输入与派生件

成员正文经独立的授权读面获取，服务端每次复核有效 grant 和当前会话；无权和不存在同为 404，响应使用 `private, no-store`。新增授权、接收人和私有内容不进入通用列表、搜索、待办、批注、交接、预览或团队事件；普通候选对照仍沿用原可见性。受管来源 Run 和候选从创建起持久继承其来源限制，团队投影最多有固定运行状态，禁止模型标题、摘要、错误、正文及其他候选元数据，邀请前后都一样。A/B 的授权读面不复用团队缓存或签名直链。

原件的正式发布仍由 A 经原入口明确决定，但 Hub 必须核对全部上游均允许对发布受众公开该派生内容；只准向 B 交付或权利未知时，普通发布入口也拒绝。允许发布时，发布与私有 grant 失效同事务提交，已有 Run 不切换到正式材料路径。c3b 密封派生件始终适用下文禁止发布的规则。

Agent 用途另存不可变的私有输入快照。B 经统一 Run 创建事务显式选择授权件，固化 grant ID/代次、Artifact ID/摘要/字节数及目标 Run/Task/Agent Revision/Device 绑定，并原子认领一次授权。重复创建仅返回原 Run；不得换设备或启动新 Run。拒绝所有通用 followup、队列注入、重跑/续跑、会话 resume、插件及交接输入回落。接收、冻结、投递、实际工具读取、草稿就绪、正式验收分别记账；授权或冻结本身不触发派工。费用、责任人、单活跃约束、资源和次序守卫继续复核，不由 A 的 Mandate 代付或授权。

- 独立通道保留 [ADR-0016](./0016-run-artifact-input-snapshot.md) 的已发布材料快照与 [ADR-0017](./0017-task-agreement-and-handoff-boundary.md) 的正式交接、接收和采用语义。私有交付无已发布版本，不占用正式交接回执，也不把草稿接收当作完成、签收或业务确认。
- 新通道只发送固定清单，正文按需经设备与 Run 绑定的受控读取返回，由 Node/Runtime 核对摘要。能力缺失、权属不符、断网、权限未知或版本漂移时拒绝，不降级到 `read_artifact_input`、`read_work_input`、追问、交接文本或通用文件工具。只启用受管执行现场：用 OS 隔离将私有根、会话、临时副本和进程与普通 Run/Workspace 分开，普通读根、软链或同设备的其他 Run 无法访问；当前由成员完全控制且无法验证隔离的通用现场不启用 c3b。
- Runtime 无直连模型或通用网络能力，也不持有可绕开检查的模型凭据。唯一模型出口由受控代理逐次核对 Run/现场、grant 代次、Agent Revision、端点/账户/模型、当前用途及费用；真正向外发送前消费一次性裁决。DSH 后续轮次、SDK 重试、重定向、收尾/压缩请求同样走该门，不能受控的路径禁用。用户确认时说明实际模型接收方，禁止将正文写入通用请求日志、追踪或错误日志。只做 tool allowlist、配置检查或撤销推送不能开放 c3b。
- Run 在创建时即写入上游 grant 血缘和持久密封标志。Node 仅产出固定的无正文项目状态；Hub 在接纳和落投影前按持久标志校验，不信任客户端的 `audience`。消息、工具回执、最终摘要、错误、自动交接、派生文件及预览不得进入团队 HTTP/WS 实时或回放、Router、项目事实、通用交接或其他 Agent。允许的状态不带 grant、私有候选或来源 Run 的身份与关联，不推动原 Task 的正式交付状态。只保留固定私有候选输出，不依赖正文扫描。
- 派生件仅供目标责任人在上游授权仍有效时通过私有读面读取。Hub 的普通候选下载（含 owner）、发布、详情/历史、预览、Artifact/交接输入和后续 Run 等入口按密封标志拒绝；采集器不能将私有输出登记成普通候选。不得转授权、回传给来源人、进入团队审阅或解除密封；更改媒体类型、标题、路径或改派不例外。普通候选的既有发布行为不受影响；允许解密、回传或多跳继承须另行评审。

### 4. 撤销、并发和已经交付的内容

A 可撤销、B 可拒绝或结束自己的授权；到期、任一成员停用、来源 Task（或已绑定的目标 Task）改派或不可用、关联 Mandate 停止或换版、来源依据失效、原件不再是该候选均使相关 grant 失效。目标现场授权撤销终止该 Run 的派发、读取、模型请求及结果提交；它不单独撤销 B 的人读原件权限。任何凭旧幂等回执的重放仍须现态判权。

- Hub 在同一事务推进撤权代次并收回新操作的权限。人/设备下载、Run 认领、派发、模型调用和结果登记都在最终出站/提交边界读取同一当前代次，以与撤权互斥的事务或原子条件记载一次性操作裁决，绑定主体、对象、Run/版本和请求摘要。初检、排队、已发标记和旧本地许可均不等于裁决。裁决不跨重试、重连或另一端点复用；不在等待网络期间持有数据库锁。
- 撤销先于最终裁决时不发送正文、不开始该模型请求或登记结果。已经准入的单个有界传输或模型调用属于在途，能中止则中止；已交付字节不能收回。新下载（含重新请求片段）、续租、后续模型调用和迟到结果都须重新裁决，旧回执只对账；已排队而未准入的 Run 不再派发。先卡住最终出口前的操作、提交撤销再放行，必须观察到没有首字节或模型 POST；同时验证相反顺序只允许已准入的一次在途。在线裁决、后续工具和结果提交任一缺失则关闭 c3b。普通机器 Run 的失效规则不改变，旧 Run 终态不复活。
- Hub 停止下发受影响的私有投影/派生正文，保留不含正文的历史身份、摘要与消费回执。Node 的隔离缓存、spill、会话、草稿副本和未送达队列通过持久清理收敛；在线受管副本以 24 小时内清理为验收目标，离线副本保持待清理，恢复时先完成隔离和清理再允许此用途继续服务。没有清理事实不能报已清。密封派生件的正文清除须考虑相同摘要的其他合法引用，不能误删来源原件；若无法隔离或证明清理，保持 c3b 关闭。此类会话不自动 resume。该边界只覆盖 WhalePod 管理的存储和后续使用，不承诺清除已读者自行保留的副本、模型已经收到的内容、人的记忆或既有合法公开版本。

### 5. 部署边界

既有候选与历史 Run 不回填 grant 或目标接收人。c3a 的阅稿通道不依赖接收方 Node/Runtime，但须先交付并验证受管来源档、继承权限与按件读面。c3b 需在新 Hub 与声明且实证支持私有草稿输入的 Node/Runtime 间启用，旧设备只获得固定升级原因，收不到正文或未知帧。某件来源授权无法证实时，两种用途都拒绝。仅 c3b 的设备隔离、模型出口、私有投影或清理链缺证据时，保留已验证的成员阅稿能力。

## 验证登记与退出条件

以下是各切片的退出判据，尚无本 ADR 的实现或机器证据。实施时登记独立验收、取证地图与可复跑脚本；协议、安全策略和 migration 至少两名独立评审。证据包按 grant/代次、Artifact 摘要、Run、回执与阶段关联，只存不透明身份及稳定诊断。用生产 HTTP/WS、真实 PostgreSQL、Node 和 Runtime 验证；模型响应可在受控出口下游回放，禁止直插业务状态或绕过权限与派工入口。除 Q0/Q1 外，数据和权限覆盖 Q2/Q7，受管来源与接收执行涉及的协议、运行时和故障覆盖 Q3/Q6；有读面 UI 时加 Q5。

| 场景 | 必须观察到的结果 |
|---|---|
| 三成员与管理员 | A 正常产出后显式授予 B，接受前 B 与其他成员的授权正文接口同为 404；接受后只有 A/B 能读该版本。无关成员、管理员、错会话、错项目、旧链接、仅在团队中或只收到通知均无法得到正文或新授权关联；原普通候选对照投影不变。 |
| 来源与用途隔离 | A 能读但不可转授、B 无该来源用途、普通 Workspace/旧会话/旧文件无法证明闭合、模型接收方不符均拒绝对应授权。用只准交付 B 的材料将标记写入来源候选标题，邀请前后的团队事件均无标记，A 走普通发布也被拒。仅阅读 grant 无法冻结 Agent 输入；模型不得经普通工具、插件、SDK 重试或收尾绕过出口。 |
| 单次 Agent 消费 | 两个真实 Run 与两套现场，第二 Run 由 B 经合法入口启动。来源/字节摘要/Grant/实际 Device 一一对上，Runtime 的真实读取与持久回执证明消费。并发、重复点击和断线重试仅返回同一 Run；选错 Agent/Task/设备、旧 Node、摘要不匹配、Task 已进入正式评审均拒绝，Task 状态保持不变。 |
| 权限与版本竞态 | 覆盖授予→撤销→下载、冻结→撤销→派发、已下载→撤销→下一工具/模型调用、上传结果与撤销竞争、改派/停用、被继承的来源授权撤销、同名新版与旧代次重放。未读字节不送达；已授权交付后的旧回执仅对账；不启动下一 Run、不改写历史快照。 |
| 私有派生及故障恢复 | 把私有标记放入最终回复、工具结果、错误和派生文件；普通 owner 下载/发布、HTTP/WS 实时/回放、Router/交接及同设备普通 Run 的文件访问均不得读到。撤销后私有历史不可读，旧队列和本地副本按目标清理。失败/重启不发布、不复活授权、不误删合法引用。逐项移除关键守卫时独立判定应变红。 |

本 ADR 合入后登记实施 Issue：RD-03c3a 先做受管来源档与权限继承，再交付按件授权和成员读面；RD-03c3b 先验证接收现场、模型出口、撤权和密封投影，再接单次真实 Run 消费。两阶段分别验收；仅完成 c3a 时不开放 c3b。

## 不在范围内

自动发现或创建新工作/Task/约定，自动跨成员派工，同一活跃 Run 动态输入，跨项目或跨 Team 共享，团队级候选 ACL，给 Router 开放私有材料，任意多个接收人、多跳转授、派生件解密发布，自动对外发送或承诺，以及恢复暂停的 Office 预览。若 c3a 证明按件交付已足够，c3b 可继续保持未启用；若需要开放更宽范围，先重新审查授权、派生和可验证隔离边界。
