# 任务消息与文件审阅：可读性验收

- 对应 Issue：#550，来自 #442 双人试用；前接 #548 的双草稿与恢复。
- 2026-11-16 在原演示项目复看两版交接单，并在独立装配回归。模型使用回放；本次不评价模型质量或协作效率。

## 路径与判据

| 用户动作 | 通过条件 |
| --- | --- |
| 打开任务，点「请助手处理」 | 界面指明实际选中的对话；有同次处理发布的文件就用标题，否则用真实开始时间。详情只打开这一次记录。 |
| 原对话不可继续、原电脑离线、或没有可用电脑 | 分别说明原因。继续编辑不会发出；开始新对话保留文字，不绑定旧聊天。电脑恢复也不会自动发送。没有可用电脑或助手仍忙时不提供注定失败的新对话入口。 |
| 从发送区看任务要求 | 能看到要做什么、限制和完成条件；查看不发送。启用且无已确认要求时禁止开始新的处理；文件历史仍用生成时的版本。 |
| 给团队留言并引用第 2 版 | 选项只有已发布文件；引用以文件名显示，不改正文。团队看到可打开精确版本的链接。历史处理记录引用仍可打开。 |
| 从待审阅文件进入 | 正文和同事意见先显示；「看修改」到对照与确认，文件校验码与历史来源可展开。新版发布不等于意见已解决。 |

## 驱动与观测

```bash
pnpm check
pnpm exec tsx scripts/run-conversation-acceptance.mts
pnpm exec playwright test --project=p1-07
pnpm test:e2e:delivery
```

- 浏览器走正常任务页、批注、发布和团队留言；检查发送请求、准确版本的链接和实际打开的文件。
- Web 测试用任务页读接口验证目标对话、草稿、权限和恢复动作；发给团队与发给助手的请求分开计数。
- `pnpm check`：252 份测试文件、3171 项通过。连续对话生产装配的判定器核对了 128 项；已关闭的聊天与电脑离线同时发生时，重连不会恢复旧聊天。
- 原 #442 演示中核对了「双人内测交接单｜第 2 版」的来源记录、不可接续状态及原用项目材料；点开始新对话后文字保留，零业务写请求。桌面审阅打开即可读文档，移动端未出现横向滚动。

## 取证与排查

- 原演示的脱敏核对：`artifacts/evidence/readable-task-review/preview-summary.json`。
- 对话与离线恢复：`artifacts/evidence/conversation-flow/result.json`。
- 独立装配的交付证据：`artifacts/evidence/handoff-loop/result.json`；`pnpm test:e2e:delivery` 会在末尾调用判定器。194 项通过，浏览器还独立检查了另一成员能从团队留言打开新版。
- 如果对话名不符，查任务对应文件实际关联的处理记录；如果动作和环境不符，查来源对话状态、设备和目录读面。审阅页的历史要求按文件来源取得；未发布文件的可见性由服务端判定。

本次只改变网页呈现和操作入口；会话隔离、审批、自动派工、正式阅稿与飞书接入没有变更。新增体验仍需团队试用。
