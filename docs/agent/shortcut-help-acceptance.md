# 键盘入口可见性验收（P1-UX-16 / #265，父账 #243 后续·P1-UX 三期刀四）

## 这条切片改变什么

本批次最薄的一刀：**说明书**。全仓真实快捷键只有三条（外加本刀新开的 `?`），
此前除搜索钮上那个 `⌘K` 角标，没有一处说得清「支持哪些键」。

- 任意已登录页按 `?` 打开「键盘快捷键」面板（`apps/web/src/app/ShortcutHelp.tsx`）；
- 搜索浮层空态顺手教一次键位（⌘K 呼出 / ⌘↵ 提交 / ? 查看快捷键）。

## 硬规则：只列已实现的键

面板是**说明书，不是愿望清单**——为填满面板而新造快捷键是另一种撒谎（列出来按不出，
人按了没反应比不知道更糟）。今天列的四条各有可按性判据：

| 面板条目 | 可按性由谁证明 |
|---|---|
| ⌘K / Ctrl+K 全局搜索 | `global-search.spec.tsx`（⌘K 呼出）+ #263 的三类实体 |
| ⌘↵ / Ctrl+↵ 提交 | `comment.spec.tsx` / `instruction-composer.spec.tsx` |
| Esc 关闭浮层并还焦 | `global-search.spec.tsx`（Esc 还焦）+ `feedback-consistency.spec.tsx` |
| `?` 打开本面板 | `shortcut-help.spec.tsx` 本文件 |

新增快捷键时两处一起改（实现 + 这张表）；验收文档的这张表就是「面板不吹牛」的账本。

## 交互契约

- `?` 只在**非输入焦点**时触发：`INPUT/TEXTAREA/SELECT/contenteditable` 里打问号是正常输入
  （中文语境里 `?` 很常见），抢它会把「打标点」变成「弹面板」。
- 修饰键组合不触发（⌘?/Ctrl?/Alt? 不是我们的绑定）。
- 面板本身没有别的可聚焦内容 → 给一个「关闭」钮并 `autoFocus`：键盘/读屏用户进来焦点才落在
  面板里（否则 `aria-modal` 说了模态、焦点却留在背后的页面上），Esc/点它关闭 → 还焦触发元素。
  **这条是被变异自测逼出来的**：初版没有关闭钮时，「还焦」判据是空转的（焦点压根没离开过触发元素，
  掐掉 `focus()` 也全绿）。
- Esc 由 vendored Modal 统一处理（同 ConfirmDialog/GlobalSearch 口径）。

## 驱动与判定

- **Q1 web**：`apps/web/tests/shortcut-help.spec.tsx` 4 例——`?` 开面板且四条内容齐全；
  输入焦点里打 `?` 不触发（问号进输入框、面板不出现）；Esc 关闭并还焦触发元素；
  搜索浮层空态含快捷键提示（发现路径不只靠记住 `?`）。
- **变异自测**（门要能被证伪）——三刀全红：
  | 变异 | 结果 |
  |---|---|
  | 去掉「输入焦点不抢键」守卫 | 红（搜索框里打 `?` 弹出面板） |
  | 去掉「Esc 还焦」（`triggerRef.focus()`） | 红（初版没红 → 补关闭钮后才红，见上） |
  | 去掉搜索空态的快捷键提示 | 红 |

## 踩坑记录

1. **空转的判据**：面板无可聚焦内容时「还焦」永远成立——判据要能区分「还焦了」和
   「焦点根本没动过」。修法是给面板一个 `autoFocus` 的关闭钮，让焦点真的进过面板。
2. **rebase 冲突的重贴**：本刀基于 #264（⌘K 三类实体）之前的 main 开发，落点提示与
   GlobalSearch 的空态行是同一处；C 合并后 stash pop 冲突，取 C 的新版重贴那一行即可
   （而不是保留旧文件结构）。顺手记一条自己的手滑：`git checkout HEAD -- <css>` 会把
   已解决的冲突一起抹掉，别在冲突解决后随手 checkout 同一文件。
3. 与 #256/#267 同族的老问题在这轮又被看到一次：`session-expiry.spec.tsx` 在整套并行跑时
   偶发红（等到登录钮后**同步**取闪屏文案），已开 #267 单独记，不在本刀修。

## 边界与债

- **不做鼠标入口**：不新加侧栏按钮（面板是给键盘用户的；鼠标用户从搜索浮层空态那行提示
  就能看到键位）。若将来需要，那属于「帮助中心」而不是本刀。
- 不新造快捷键；不做命令面板/动作类命令（⌘K 的另一档，见 #263 边界）。
- 窄屏与宽屏同一套（面板宽度 `min(420px, 90vw)`）。
