## 一句话总纲

下一阶段从**功能建设转向可发布性验证与真实协作价值验证**。核心目标不再是持续完善一个通用
Agent 协作平台，而是以最小、可靠、可验证的产品形态，证明"两名成员能围绕同一个 Task，在各自
私有 Workspace 中用不同 Agent，安全地执行、观察、审批、接管并交付"，且该过程比
Agent CLI + GitHub + 团队聊天的传统方式有实际优势。顺序是：**先发布、再验证、后强化 Handoff**；
成功判据只有一条：真实团队能低摩擦地完成跨成员、跨 Agent、跨 Workspace 的可信工作交接，并愿意持续使用。

## Phase 2：External Alpha Validation（最高产品优先级）

目标不是继续优化前端，而是观察安装→邀请→配对→运行→观察→审批→接管→交付每一步卡在哪。
用户没走通闭环时，先定位（Node 离线 / 未受理 / 被拒绝 / UI 未更新 / 不理解指令权 / 协议缺陷），
不直接设计新气泡。

- 招募 3 个真实团队，每队 ≥2 人：熟 Agent 工具、有真实共同任务、能部署 Compose、用不同设备、
  不靠作者手把手。先证 2 人成立，不测 10 人。
- 六阶段验收：环境建立 → 首次执行 → 审批交接 → 跨 Workspace 接管（B 用自己 Workspace 起新 Run，
  明确继承什么，不错继承 Alice 本地 Session）→ 验收 → 任选一次故障（Node 断连 / Runtime 崩溃 /
  取消 / 审批拒绝），验证双方能否理解发生了什么。
- 预注册成功门（实验目标，非统计标准）：2/3 团队独立安装、2/3 完成真实双人闭环、每成功团队至少
  一次跨 Workspace 交接、0 越权、0 错误重复副作用与终态复活、0 高危泄露、成员能讲清
  Run/Task/审批/交付物区别、至少 1 队自发再用、至少 2 队说清省了什么协作成本。
- 预注册失败信号：只用单 Agent 从不协作、当远程聊天用、不愿配第二 Node、认为 PR+聊天更简单、
  夸界面但不再打开。成功定义：用户确实完成一次没 WhalePod 更难的协作，且愿再用。
- 对照实验（与 CLI+GitHub 对照同一团队相近任务，交换 A/B 顺序）：接管耗时、人工上下文传递次数、
  错误上下文次数、部署管理成本、审批越权、完成时间、再用意愿。探索目标：在目标场景接管降约 30%。

## Phase 3：Evidence-driven，最小 Handoff（Alpha.2 起，有证据才开工）

产品定义换掉"多人多 Agent 多 Workspace"（系统结构），改成用户价值：

> 一个人的 Agent 工作，能被另一个人安全地理解、验证、接管和继续，不要求共享完整环境、密钥和原始会话。

最小 Handoff Package 复用现有 Task/Run/Approval/Artifact，不先立独立状态机：任务目标、
已完成、未解决、Run 血缘、Git 基准与提交引用、测试结果、经确认共享的 Artifact；区分系统事实
与 AI 总结；接收方查工作区兼容性（仓库身份、基准/目标 Commit、未提交修改）、确认继承内容、
自行起新 Run；严禁自动共享原始 Session、密钥、绝对路径；交接上下文不隐式授权。Git 集成先用
引用/PR URL，不做双向同步。决策表：看不懂执行状态→做 C1 可观察性（被拒反馈、运行状态、
取消进度）而非 C2 视觉打磨；必须传截图→最小附件；分不清落点→改进身份展示；因深色拒用→再议
#236；嫌两设备重→优化安装配对；实际只用单 Agent→重审定位；反复跨 Agent 交接→加投核心模型。

## 工程治理与范围控制

- **门禁重分级 G0/G1/G2**（需先读 `04-验收矩阵` 全文再落表）：G0 安全正确性硬门禁
  （认证授权、Approval 归属、终态不可复活、取消重试不变量、投影安全、协议兼容、迁移完整、
  真实装配 E2E）失败禁合禁发；G1 日常质量（生产 typecheck、新增测试类型、单元集成、lint、构建）；
  G2 观察证据（20 连跑、长稳、视觉、深色对比度、大 UX、深度性能）按风险版本触发。六原语按风险减法，
  普通 UI 不付分布式故障测试成本。
- **无第二 reviewer 的处理**：AI 自查 + CI 绿不包装成第二人 Review。高风险变更缩范围、
  加不变量测试与故障注入、明示残余风险，发布前争取一次外部工程师审查。
- **UI vendoring 冻结线**：L1/L2 保留，L3 禁止；L2 目标是变成自有组件摆脱同步。触发任一即冻同步：
  维护连两月超前端 15%、连两次同步超一天适配、被复制件开始要 DSH Session/Host 依赖、为追 DSH 改
  Task/Run 语义。（ADR-0008 边界保留，竞争力不在"像 DSH 的聊天界面"，在团队协作语义。）
- **DSH 熔断**：分 UI/协议/语义/安全四类 drift；建 Runtime Capability Contract
  （sessionResume、单 Run 隔离、中断模式、审批桥、指令回执、事件流范围）；四规则：未知事件不给权、
  建不起归属不确认成功、敏感不兼容禁启动、升级失败回滚固定版；生产 Alpha 锁一版，新版走独立分支；
  熔断点放 Adapter/Node 能力边界，不进 Hub 领域模型（守 ADR-0001）。
- **分布式诚实语义**：Outbox 保交付不保副作用 exactly-once；补 `outcome_unknown`（名可议）、幂等接收、
  旧执行者 fencing、取消分请求与完成；子进程杀掉不等于其子进程/外部任务已停。改状态机走 ADR。
- **附件 #266 冻结**：拆成 Task Attachment / Artifact / 私有文件三对象；最小形态仅显式上传
  txt/md/PNG/JPEG、2MB、明确告知团队可见、不可变 ID+哈希、可删、有保留策略、鉴权访问、
  不自动进 Agent 上下文、选中才交付某 Run；不做 Embeddings；小规模可暂放 PG（限大小、验 MIME、
  安全头、权限、备份删除、不写日志）；密钥截图只做最佳努力检测 + 显式确认预览，不承诺拦。
  无真实阻塞则继续冻结。
- **暂缓/不做**：深色 #236、多 Team、Project ACL、插件市场、多 Runtime、移动/Electron、L3、
  全自动跨环境迁移、通用环境克隆、AI 自动协调卖点、不做另一个 GitHub（代码事实归 GitHub，
  WhalePod 只持有执行过程、授权事实、交接关系；先用 `Task ↔ Run ↔ Handoff ↔ Commit/PR ↔ Review` 引用关联）。
- **命名冲突**：GitHub 已有 `whyihaveyou/whalepod` 同名不同定位，核对名称混淆、npm scope 所有权、
  README 品牌识别、商标许可，不阻内部 Alpha，公开传播前解决。

## 发布限制声明（v0.1.0-alpha.1 必须附带）

只面向互信团队；DSH Runtime 仍 Preview；不保证不可信插件强隔离；不保证外部工具副作用可撤销；
不提供 Project 级私有 ACL；附件暂不支持或受限；未知等于不公开（Unknown 默认不展示，需用户主动共享）。

## 落子顺序

1. 读 `04-验收矩阵` 全文，把 Q0–Q9 落到 G0/G1/G2。
2. 按 Phase 1 的 1–3 开工（#199 复现定级、#99 关键路径、#256 去 sleep），每批独立 Issue→分支→PR。
3. 同步补 8 项安全负向测试与 Compose 空卷验证。
4. 发 `v0.1.0-alpha.1`（带限制声明）。
5. 启动 3 队 Alpha 跑对照。
6. 有证据再开最小 Handoff，否则不扩。
