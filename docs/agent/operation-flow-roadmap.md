## 第二批：首次用户与协作者路径

1. #319 操作条件与处理人：服务端返回验收条件，条件缺失不当作可提交；具体责任人、环境及审批说明；无权成员定位讨论，权限管理仍独立。
2. #320 首次执行准备：既有 Node inventory 的本机配置事实与时效；固定版本/目标的检查；配对、工作目录、本机凭据修复步骤；显式试运行，不自动调用真实模型。配置存在与模型调用通过分别表达。
3. #321 撤销与交接：尚未入 Outbox 的追问重新判权；拒绝落状态/原因，合法指令正常派发；已可投递或已交付的不宣称撤回。进行中仍禁止改派，授权名单保留，历史候选与会话归属不变。

每个 Issue 一个 PR，相关测试先红后绿，验收结果脱敏入 artifacts/evidence 并登记文档；协议/安全策略走两份独立评审后合入。原工作目录的 #312 修改不纳入这批。

## 第三批：交付闭环

- 固定 Reviewer Run 的交付物身份/内容摘要快照，新增交付物不改变旧复核对象。
- 从产出发起复核；明确当前活跃执行的阻塞与输入范围，不把输入只读说成整个运行只读。
- 根据意见修订时明确产出 Agent 和来源会话，不自动继承 Reviewer。
- 连接发布、可选复核、提交验收与真人完成；复用已有 in_review → in_progress 迁移。

## 后续试用

先以首页小区域验证“需要我处理”，按权限与候选拥有关系聚合，处理后及时消失，定位具体行动；再以真实团队的查找表现决定是否扩展工作台。

陌生用户自助试用需第二批准备流程通过；机器验证覆盖真实 HTTP/WS/生产 Node 路径，理解成本仍需真人试用。真实模型凭据与远端 provider 的调用不由 replay 测试代替。
