# 第三批：交付闭环实施方案

背景：前两批已合入#316–#318、#322–#324。现有发布与运行路径存在，但Node在派发时实时查当前已发布材料，复核区只有文字，修订容易默认接续最近Reviewer。本批补齐P1-15/P1-06/P1-07，不新增验收角色或自动完成规则。

## 顺序与交付

| 工作包 | Issue | 实施与可证伪判据 |
|---|---|---|
| 输入快照 | #325 | 创建Run时同事务固定manifest；晚发布、迟到启动、重复拉取不得改变旧清单；显式选择只接受同Task的已发布身份，最多64项；无材料固定为空，旧未知与空不同 |

依赖按#325→#326→#327组织，每个Issue一个短分支和Draft PR；使用独立组合分支验证三者。原工作目录#312的修改不动。

## 承重边界

输入固定在Run创建事务而非Node第一次下载；默认新执行只查询一次当时已发布集合，显式artifactInputIds为精确选择。续跑/重跑默认继承来源快照，显式材料选择只改变本次新Run，历史不变。追问不更新运行输入。全部版本/目标/审批和单活跃、指令权限守卫复用生产入口。

迁移不猜既有Run历史：旧行manifest=null，成员界面说明未知，Node拒绝未知；已运行的Runtime不强制终止，新建或显式选择材料后重跑可恢复。空数组是已确认无输入，不能与未知混淆。新旧Hub混用须升级服务端后启动新工作；不升级DSH或Runtime wire。

只读仅指受控交付物副本。复核Run仍可使用当前Agent工具和审批设置；不承诺整个运行只读。续跑保留历史会话，不声称清单等于全部上下文。输入不含本机路径/秘密；已发布材料仍按既有团队权限读取，候选只有拥有者查看。

## 验证与验收

先失败检查可在提交历史中复核。#325跑协议/迁移Q0和真实HTTP+WS+PG Q2；#326/#327跑实际网页动作、草稿/来源/审批/权限变化检查和生产Hub/Node/Runtime Q5。综合链路：Builder产出→拥有者检查与发布→指定材料复核→意见发布→明确返回产出会话修订→重新发布→提交验收→真人完成；另外证明晚发布不改变旧输入、无权限拒绝、活跃Run不改投。影响共享P1-19装配时全量Q5。

证据脱敏写artifacts/evidence/operation-flow-batch3/，验收登记docs/agent索引及evidence-map。协议/migration至少两份独立评审，开发完成先开Draft PR，按评审阶段处理合入。
