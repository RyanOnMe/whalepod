# 飞书只读可行性探针准备（PC-01 #448）

- 状态：准备清单；真实租户/应用/群/文档尚未提供，PC-01 保持 `not_run`。
- 关联：[计划](../agent/2026-10-30-project-context-coordination-plan.md) §7、[ADR-0024](../adr/0024-source-sharing-and-revocation.md)（来源共享、身份映射、撤权）、[ADR-0025](../adr/0025-source-revisions-and-project-understanding.md)（修订身份）。
- 纪律：除安装、授权与撤权这三类管理员操作外只读；不向真实群自动发送试探消息；不把开放平台文档或上游 CLI 实现当成已证实的团队权限。

## 需要用户提供的最小条件

| 资源 | 要求 | 用途 |
|---|---|---|
| 租户 | 可安装企业自建应用；管理员可授予只读权限 | 证明应用级读取，而非个人令牌 |
| 应用 | 机器人能力已启用；只读权限按下面的能力清单勾选；可随时撤权 | 正向与撤权负控 |
| 测试群 | 两名真实成员（其中一人可发消息、可编辑/撤回自己的消息）；机器人已在群内；两名成员书面同意只读采集与平台 id 记录 | 普通讨论、编辑、撤回、身份 |
| 测试文档 | 一份可被应用读取的云文档，范围明确；内容为合成测试材料 | 文档版本与越权 |
| 测试表格 | 一个可被应用读取的表格范围（工作表或区域）；内容为合成测试材料 | 范围与修订 |
| 凭据保管 | 应用凭据只放采集 Node 的 SecretStore；不进聊天、不进仓库、不进日志 | ADR-0024 §4 |

需要用户明确回答：

1. 是否允许机器人在测试群内**只读**历史消息（不发送任何消息）？
2. 应用由谁创建、谁负责续期与撤权？管理员操作是否需要额外审批？
3. 测试文档/表格是否允许把**脱敏后的**片段写入本地证据包（不提交 Git）？
4. 协调模型与采集 Node 是否允许分属两台已授权设备？（首轮可都放在同一台）

## 入口选择：CLI 还是官方 SDK/API

上游 `dsh-superagent-prototype` 使用 `lark-cli event consume` 长连接 + 群历史/线程补拉。它是**候选**，不是 WhalePod 已验证入口。探针同时评估两种入口，按同一张表打分后二选一：

| 维度 | 机器人 CLI（长连接） | 官方 SDK/API（订阅 + 拉取） | 判定方式 |
|---|---|---|---|
| 普通群消息（不 @ 机器人） | 待测 | 待测 | 测试群发一条普通消息，确认能读到 |
| 历史补拉 | 待测 | 待测 | 断开后补拉，核对缺口与顺序 |
| 消息编辑/撤回事件 | 待测 | 待测 | 同一消息先发后改、再撤回，记录事件与版本 |
| 线程/父消息 | 待测 | 待测 | 回复消息的父消息与线程范围 |
| 作者身份 | 待测 | 待测 | 平台 id 与显示名；不按显示名映射成员 |
| 文档/表格范围 | 待测（上游未覆盖） | 待测 | 只读一份文档/一个表格范围，取稳定修订或摘要 |
| 版本语义 | 待测 | 待测 | 是否有修订号/更新时间；没有则重读比较摘要 |
| 越权拒绝 | 待测 | 待测 | 未授权文档/未加入的群必须明确拒绝 |
| 撤权与断线 | 待测 | 待测 | 撤权后下一次读取失败；断线重连不丢代次 |
| 部署与维护 | 待测 | 待测 | 是否需要公网回调、进程常驻、升级与证书 |
| 费用与限流 | 待测 | 待测 | 读取频率、配额、超限行为 |

选择规则：

- 只读能力满足上表全部正向与负控、且维护成本可接受者胜出；两者都不满足则记录原因并考虑其他平台，不用手工转发替代。
- 若只有用户级授权能读普通群消息，必须如实记录：ADR-0024 的「应用可读 + 绑定者确认共享」假设不成立，需回到 ADR 讨论，不能把成员令牌当团队来源。
- 精确的权限 scope 字符串以开放平台后台当时可勾选的为准，探针记录**实际勾选清单**与拒绝结果；本文件不预先编造 scope 名。

## 探针步骤（真实租户，一次一人，全程只读）

1. **安装与授权**：管理员创建/安装应用，勾选只读能力；把机器人加入测试群。记录应用 id、权限清单、安装时间（不记录密钥）。
2. **普通消息**：成员 A 发一条不含 @ 的消息；Node 读取事件并回读该消息。预期：能读到，作者 id 稳定。
3. **编辑**：A 修改该消息；确认是否产生新事件/新修订号或只有更新时间。预期：能区分「同 message_id 新正文」，不能把两次观察拼成一个版本。
4. **撤回**：A 撤回消息；确认事件与读取结果。预期：撤回可见，读面停止使用该正文。
5. **线程**：A 回复一条消息；确认父消息与线程范围可读，且不越出绑定范围。
6. **历史补拉**：停止采集一段时间后重启，补拉期间的消息；记录缺口与顺序。预期：补不齐时显式记缺口。
7. **文档**：读取一份测试文档的正文与元数据；修改后再读，确认修订号或内容摘要变化。
8. **表格**：读取一个表格范围；确认范围边界与越界拒绝。
9. **越权负控**：用同一应用读取未授权文档/未加入的群；预期明确拒绝，不返回正文。
10. **身份映射**（可选；标记 `blocked` 直到 ADR-0024 §3 的映射表落地）：成员在 WhalePod 生成一次性码，用自己的平台账号在测试群发送；Node 只读上报发送者 id + 码。**这条消息由真人发送，不由系统发送**。产品能力未落地前本步不执行，也不得用手工转发替代。
11. **断线与重启**：断开长连接/回调，重启 Node；预期租约到期、不静默续租、不丢已确认水位。
12. **撤权**（放最后，因为会破坏后续读取）：管理员撤销一项权限或移除机器人；预期下一次读取失败，Hub 来源转 `unknown/unavailable`（按 ADR-0024），旧代次结果被拒。

每一步记录：时间、操作者、入口（CLI/SDK）、请求类别、结果（成功/拒绝/缺口）、可脱敏的证据摘要。不记录 token、tenant 密钥、完整正文与成员姓名；平台 id 在证据中做哈希，本地只保留一份受限对照表（采集 Node 的私密目录、仅本次探针操作者可读、探针结束后 7 天内删除并记录删除时间），不进入仓库、聊天或团队投影。

## 观测与判定

- 结构化记录：`platform`、`entry`（cli/sdk）、`capability`（message/edit/recall/thread/history/doc/sheet/auth）、`outcome`（ok/denied/not_found/unsupported/gap）、`latencyMs`、`revisionTokenKind`（platform/content-digest/none）。
- 判定：表中每一项必须有明确 `ok` 或 `denied` 结果；「可能可以」「文档说支持」不算通过。
- 负控失败（例如越权仍能读到）立即停止探针，按安全事件处理，不带回正文。

## 证据与脱敏

- 证据包目录：`artifacts/evidence/pc-01/<attempt>/`（不提交 Git）；每步一个 manifest，保留失败尝试。
- 禁止项：完整群聊、完整文档、成员显示名、租户/应用密钥、token、本机绝对路径。
- 允许项：能力清单、权限 scope 名、结果类别、修订令牌种类、时延、脱敏后的片段（≤200 字符，经成员确认）。
