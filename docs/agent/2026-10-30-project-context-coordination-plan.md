# WhalePod 项目上下文与多人 Agent 协调开发计划

> 初稿：2026-10-30；本次修订：2026-11-02（Asia/Shanghai）。状态：阶段计划与 Router 扩展讨论稿；已交付切片见 §2 与 §13。研读基线：`93f41e9`（含 PC-03a/04a/05a；初稿时为 `e5bf468`）。上游参考固定为 `dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e`。PC 编号是工作包编号；只有列出实际编号的才是已登记 Issue。

## 1 阶段目标

让成员照常在办公工具和各自 Agent 中工作，WhalePod 从正常讨论、资料修改和执行结果中持续理解项目，承接已有工作的变化并发现新缺口。成员无需另填进度、日报或上下文表，也无需为每次变化重新整理背景、@Agent 或编写执行提示词。

根据[上游源码复用分析](./2026-11-01-superagent-reuse-analysis.md)与用户 2026-11-02 的方向确认，目标主链调整为：**日常环境变化 → 快路径承接已有工作 → 必要时慢路径理解新缺口 → 授权内自主执行并产出草稿 → 人处理业务取舍与正式发布 → 结果继续更新项目理解**。已归属的普通补充直接送到承接工作，新工作或超出原范围的内容才进入 Router 的语义判断。入口准入另以程序规则过滤来源、权限、重复和明确无关事件，必要时再调用模型。具体行为见 [Router 与 Executor 自主派工方案](./2026-11-02-router-executor-autonomous-dispatch-plan.md)。

阶段交付同时满足以下结果：

1. 两名成员分别工作后，任何成员重新打开项目即可看懂目标、活动工作、阻塞和待决定事项，并展开对应出处与更新时间。
2. 一次确认项目目标、持续职责与资料/费用边界后，正常工作即可更新上下文；不要求逐事件配置“发生什么就做什么”的规则。
3. 已承接工作持续订阅相关讨论，正常补充可自动交付并被后续执行消费；新缺口才由 Router 补上下文、判断归属和选择 Agent。
4. 工作意图可来自多人多条讨论，系统自动还原目标、依据和约束；已证实依赖、模型推测与正式业务决定保持区分。
5. 研究、分析和草稿在持续授权内自主执行；新缺口无需人为再建一次 Task、搬运上下文或发派工提示词。正式发布、外发与业务承诺仍由人决定。
6. 历史 Run 保留固定输入；变化交付到持续工作后，在协议允许的执行边界消费，准确区分“收到”与“已采用”。
7. 真人双人试用同时记录双方劳动、额外提示词、上下文搬运、配置、打扰、漏事、错版和返工，判断新增负担是否被收益覆盖。

协调角色是持久的项目身份和工作记忆，按相关变化有界唤醒。默认保持安静，在成果可用或确需人决定时合并提示；成员可随时查看处理水位、出处和未处理变化。现有实现继续遵守确定性协调与固定上下文 ADR；持续工作续接、机器执行意图及自动新工作先形成新 ADR。已有 Task 的自动草稿 Run 是首个工程切片，不能代替完整的持续协作目标。项目进度解释目标条件、工作状态与未知项，不自动生成无依据的完成百分比。

## 3 成员如何使用

以下“客户活动”是待验收情境。A 负责活动与预算，B 负责方案和场地，两人各自使用 Agent。成员一次确认“在指定资料、执行环境和费用内，持续研究活动方案并维护草稿”，无需预先列出预算、人数、交通变化的全部处理规则。

| 时点 | 成员正常动作 | WhalePod 自动行为 | 可见结果 |
|---|---|---|---|
| 建立项目 | A/B 说明目标，确认可共享资料、持续职责、责任人及资源费用边界 | 生成可读授权摘要，建立处理水位；区分资料可读与可执行范围 | 一次设置，不要求完整任务分解、逐变化规则或复杂授权表 |
| 分头工作 | B 正常开始场地比较与方案草稿，A 继续和同事沟通 | 记录工作身份、已消费依据与合法订阅；Task/Run 沿原权威维护 | A 看得到可共享的进展，B 无需另整理项目状态 |
| 原工作有补充 | A 在原讨论说“客户确认有轮椅使用者”，没有 @Agent | 快路径将准确消息版本送入方案工作的收件箱；承接 Agent 在允许边界自动处理 | 草稿纳入无障碍要求，无新增提示词、转发或 Router 逐条语义路由 |
| 暴露新缺口 | 成员正常讨论“高铁站到场地不好走，接驳这一块还空着” | 慢路径合并多人讨论与现有工作，识别授权职责内的新研究缺口；补上下文、选 Agent，按新 ADR 自动建立工作归属 | 接驳研究形成私有草稿；不要求人补建 Task、整理背景或指定执行者，不自动预订车辆 |
| 执行中又有变化 | A 修改预算并正常说明已确认 | 合并待处理版本；当前 Run 输入不变，执行结束后在有效授权与约定下自动续接 | 看得到收到/待处理/已采用的区别，不因每次保存打断人或起一个 Run |
| 结果与取舍 | B 在原协作入口看到草稿就绪；需要时选择方案 | 回传允许共享的状态与核验摘要；合并真正需人的问题，私有正文仍按受众交付 | 研究和草稿自动完成，正式发布、外发、业务承诺及最终验收由人决定 |
| 了解项目 | A 打开概览或询问目前在等什么 | 解释活动方案、新缺口、处理水位和未确认事项 | 能展开出处、已采用版本和未知项，无需另找每个 Agent 追问 |
| 修正理解 | A 指出某句话只是建议 | 追加纠正，更新概览、影响和后续上下文选择；阻止同输入后台重试恢复旧误判 | 一次纠正，不逐页维护 |
| 断线与撤权 | 来源停机、资料撤销或权限过期 | 暂停相关正文使用，撤销派生引用，显示缺口；恢复时按新代次核对 | 项目不假装仍掌握最新情况，旧 Run 标明依据不可重读 |

一条变化可影响多个工作，也可不产生任务。普通补充优先续接已有工作，只有确实新增独立交付、责任或生命周期时才建 Task。首个已有 Task 切片仅验证工程接线，完整场景还需自动新工作；两者分别登记，不以首切代替完成。自动建议、订阅和资料可读均不授予执行权；执行仍需新 ADR 规定的有效 Mandate 与 WorkIntent。

预算案例保留为错版验收：有效约定允许采用当前已确认预算，且新预算不与固定 Artifact 输入冲突时自动处理；若约定写死旧预算或需替换 Artifact 版本，先沿既有业务入口确认。责任人不任意改派，草稿沿用私有候选范围。初次配置、纠正误判、补来源及管理提醒都计入协调成本。

## 4 自动获取、订阅与持续理解

### 4.1 先绑定范围，再持续同步

沿用 [ADR-0024](../adr/0024-source-sharing-and-revocation.md)：一条来源绑定一个明确群、线程、文档或表格范围，由绑定者自己的 Node 采集；凭据留在该 Node。只能纳入允许整个 Team 共享的内容，Workspace 关联不构成目录分享。

同一外部资源不能同时活动绑定到多个 Project。M:N 订阅发生在已绑定项目内部，不能用跨线程关联绕过此限制。群跨多个项目且无法合法分割时，不将其全部正文自动归到某个项目。

来源可读不等于允许执行。开启自动协调还需明确模型 Node、费用承担者、日额度及处理范围；ADR-0026 已采纳，但模型派发与额度路径未实现前仍保持 `autoExtraction=false`，后台模型功能不能启用；确定性内部协调（04a）不受此限。

### 4.2 接收变化，并取得对应的真实版本

事件通知只是重读信号。消息身份、消息修订与投递事件幂等身份分开；文档/表格按资源身份、上游修订或稳定内容摘要形成不可变版本。不能沿用原型只用 message_id 去重而吞掉编辑的行为。

适配器先做来源范围、权限和租约检查，再读取与提交允许共享的内容。Hub 提交时复核当前授权代次；重复、乱序和迟到不覆盖新版本。没有可靠顺序则重读当前内容比较，不拼成一个从未存在的文档版本。

live 事件配合有界补拉和周期核对。补拉游标不能仅依据新消息创建时间假定覆盖旧消息编辑与撤回；实际覆盖不到的情况明确记缺口。只观察到两个版本，不声称抓到了每次中间编辑。

### 4.3 两处快慢路径

| 分流位置 | 快路径 | 需要慢路径时 |
|---|---|---|
| 事件准入 | 程序判断来源范围、当前权限、去重和确定归属；不需要理解的事件直接更新或过滤 | 候选内容涉及工作意图、关联或缺口时，合并相关事件后有界读取上下文 |
| 工作承接 | 已有合法订阅的普通补充直接送入承接工作的收件箱，不逐条经过 Router 模型 | 新工作、归属不明或承接者发现超出目标时，再由 Router 判断；不把整条讨论反复重新派工 |

快路径依据已有合法关系，不能用关键词猜测给事件随意定性；承接 Agent 仍需理解补充内容。程序不调用 Router 模型不等于 Executor 不需要模型。未明订阅由真实消费、Task 归属或可纠正的关联建议逐步形成，不要求成员为每类变化编写触发器。

项目协调角色以版本化检查点保存：已处理的来源水位、活动工作引用、未决问题、近期判断和可追溯依据。它在相关变化或成员询问时有界唤醒，读取短卡片，并按需要展开父消息、相关线程和资料片段。输入缺失或超限必须显式表达，不能假称读完。

工作意图可由多人多条讨论共同表达；Router 自动补齐有权读取的背景、目标、约束与已有承接，不要求最后一条消息具备完整命令格式。缺少可执行方向时继续观察；无关、假设和未定讨论不逐条追问。持续职责给出目标与边界，具体变化的理解由模型完成。

直接观察事实自动更新，例如消息作者平台身份、修订摘要、Run 状态与成果发布。模型解释目标、潜在决定、影响与问题，每项带具体引用。“考虑改为 8 万”、Agent 自报完成和未知身份自称批准，不升级为正式决定或已完成。已验证的正常业务确认可以自动关联，不再多设一次确认。

协调上下文只包含允许共享的资料与投影；不查询个人原始 Session、未分享候选和 Workspace。长内容引用不是权限豁免，每次展开、分页和模型装配都复核当前权限。

### 4.4 增量更新、恢复与成本

同一 Project 协调状态的变更在 Hub 事务内串行裁决；语义判断在事务外进行，提交时复核策略、输入版本、来源代次和人工纠正。模型失败仍保留确定性事实，读面显示理解落后于哪些变化。

检查点可从权威事件、版本和引用重建。重启只重排无业务副作用的协调计算，不自动恢复可能执行工具的业务 Run。输入/处理器/策略版本共同标识幂等评估；同输入重试不重复提醒，也不撤销人的纠正。

各来源分别显示最后成功读取、修订、水位和缺口；项目展示覆盖情况。来源断连、模型限流和业务阻塞分开解释。按相关输入合并唤醒，限制次数、并发、输入量及费用；额度耗尽时继续确定性同步，标明协调理解暂停。

### 4.5 持续工作收件箱与续接

已证实依赖来自实际 Run 材料/上下文清单和消费证据，模型相似性只作可能受影响。阅读过文件不自动等于工作依赖它。

工作身份 `workKey` 持续关联讨论、资料、Task 与执行轮次；本次依据由独立 `inputDigest` 标识。它是后台关联身份，沿用现有 Task 权威，不另建第二套业务工单系统。工作收件箱保存准确版本、投递身份、授权代次与处理结果，支持合并、断线恢复和去重；收到、交付、选入执行及实际消费分别留证。

当前已采纳 ADR 的订阅只到协调上下文与通知。拟议扩展在独立 Mandate 下让已承接工作持续消费补充：第一切片在 Run 空闲/结束边界合并领取变化，复核覆盖、约定和授权后形成新 WorkIntent，自动建立新 Run。成员无需逐次确认，也不改写活跃 Run 或借用人工 followup。已终结 Task 不自动重开，需要新工作时沿 RD-04 另建合法归属。

同一 Run 内动态接收属于后续增量上下文协议议题：须明确允许消费的步骤边界、追加输入记录、当前权限、约定冲突和逐项回执；不得改写初始快照或将订阅消息当新指令。M1R-B 可先通过 Run 边界自动续接实现；收件箱仅收到而没有真实消费，不算持续承接完成。超出原目标的事件退回 Router 重判，不能自动扩权。

后台状态更新默认安静；成果就绪、持续阻塞或确需业务决定时才合并提示。已读、忽略、稍后处理、已采用与业务问题解决分别记录。Router 不自主停止正常业务执行、审批、正式发布或外发；撤权/到期/硬额度由宿主按新 ADR 收敛。

### 5.1 保留现有架构，新增协调装配

Hub 模块化单体与 PostgreSQL 继续持有团队权威：来源版本、线程关联、订阅、协调检查点、决策/纠正、认领与 Outbox。上游核心的仓储全同步，不能仅换 Store 连接 PostgreSQL；迁写为异步事务命令，保留可独立复用的状态转换和用例。事务不跨模型等待。

Node 负责真实来源采集及受限协调计算。来源凭据留在指定采集 Node；协调模型可以在另一台已授权 Node 运行，只获得当前允许分享的版本化内容。首轮不新增共享采集者接管机制，不绕过现有 owner Node 和应用租约。

逻辑协调身份长期存在；首版优先按检查点有界唤醒，复用现有独立进程驱动、SecretStore、本机模型与 Adapter 基础。协调计算独立于业务 Task/Run，不伪装辅助 Run 占用 Task 单活跃名额。需要新增用途、任务协议、认领/取消、结果校验及额度装配；这些当前尚不存在。

拟议快路径由 Hub 按合法订阅确定性入工作收件箱，Executor 在允许边界领取；新缺口或退回事件才经 Router 模型形成结构化提案，由 Hub 授权派工端口验证后调用统一 Run 服务。模型不能直接写 Task/Run 或冒充成员。首切复用已有 Task 的有效约定；后续由持续职责/可验收模板自动实例化必要 Task，记录 Mandate、模板版本和事实参数，约定来源明确标为预授权派生，不伪造真人逐次确认。模板表达目标与成果边界，不要求为每种环境变化编写业务规则。

受限进程只读授权上下文、返回结构化判断，不装配文件写、Shell、任意网络、对外发送或业务审批工具。rc.8 能否实际实施限制由 PC-00 能力探针验证；提示词声称“只读”不算完成。限制不可验证则停在确定性路径，不能启用背景模型。DSH 模块仍只由允许的包导入，Hub 不加载上游插件。

### 5.2 持续工作与单次 Run 的准确依据

人工入口或未来合法的 Mandate 派工创建新 Run 时，在现有创建事务选取项目上下文及材料，保留约定、交接和审阅输入。普通已同步项目参考自动选入；已有 Artifact 输入继续按 ADR-0016 继承，换版本需原业务入口明确选择，不能以刷新项目参考为由静默替换。与确认要求冲突、来源过期或必要材料缺失时明确说明，由成员沿业务路径决定，不能静默截断或覆盖要求。

创建时固定本次选取的正文、版本和摘要，派发前再判权，Node 核对字节；Runtime 输入和消费结果可机器验证。参考不改变工具授权、旧审批或任务约定。重放同一启动请求返回同一快照，不重新取“最新”。新的明确执行请求才能选新版依据；拟议扩展允许该请求来自可审计的授权派工，不将 Router 的 Inference 当作人工决定。

现有活跃 Run 只提示依据变化或撤权。新方案先在 Run 边界领取工作收件箱：同一 Task 单活跃，上一 Run 结束后重新检查待处理版本是否已覆盖、约定和授权是否仍有效，再自动形成新 Run。已接收但未进入本 Run 的事件保持待处理，不能记为已采用。旧 Run 输入及历史成果依据不改写；原 Session 可能带历史材料，续接须明确新旧依据，不声称换了文件便清除了历史上下文。

同一 Run 动态消费若有必要，另行评审增量上下文协议，记录初始快照与每次追加输入、摘要、来源代次和消费步骤。现有人工 followup 的权限、排队和撤销守卫继续生效，自动订阅不能借用该通道。此能力不阻塞先实现 Run 边界的持续自动续接。

### 5.3 撤销、保留与派生失效

按 ADR-0024 阻止新采集、模型提交、读面下发及新 Run 材料交付；权限未知/到期停止正文使用。暂停、未知与撤销的保留/清除语义按已采纳规则实现，不能照搬上游保留 filtered Trigger 的行为。

正文、规范化副本、短卡片、合并理解、问题、订阅提示与快照读面共同判权。历史 Run 保留不透明版本及不可用标记；重读正文需当前权限。已交给模型的内容无法收回，活跃执行显示依据撤销，不承诺清除它已经读到的内容。

源内容清除及派生失效在 PC-03/04 同批交付；不能先启用真实正文留存再把撤权安排到末尾。Office 只读解析与安全限制另验，不重新启用 ADR-0023 已暂停的 LibreOffice 转换。

| RD-02 持续工作订阅与事件承接 | 拆为 02a 工作身份/收件箱/交付与消费（输入由成员显式关联或既有工作接收），02b 订阅快路径（有效订阅直达、证明不调用 Router）；消费回执先在人类触发的 Run 上验证，自动消费由 RD-03 联验；M1R-A 需要 02a+02b |
| RD-03 授权内自主草稿执行 | 依赖 RD-01/02；A 切片复用已接受、非终态 Task，在 Run 边界领取并固定新版依据。Mandate 明确 `autoDispatch='existing_task'` 后才无需逐次派工确认；最小转人工/撤销、受限模型工具和 PC-05b 完成后启用 |
| RD-04 新工作自动承接与人工协同 | 在已有安全执行链上识别新缺口，按一次预授权职责/可验收模板自动建立必要 Task/约定与订阅，不伪造真人确认；跨工作问题合并，回答后重验，不自动正式发布或外发。**ADR-0028 范围外，须另立 ADR** |
| RD-05 快慢路径组合与真人试用 | 已承接补充与新缺口同场成立；无新增执行提示词、搬运、逐事件规则或人为补建 Task；保留误做/漏做、越权、预算与双方成本证据 |

RD-01/02 可先做影子核验与收件箱协议；RD-03 依赖 ADR-0028 采纳、模型受限装配和 PC-05b 消费/恢复链；RD-04/05 还依赖自动新工作 ADR。推进顺序为：双路径影子 → 已承接工作直通与 Run 边界续接 → 新缺口自动建工作 → 组合试用。已存在 Task 首切记为 M1R-A，RD-04/05 通过后才可宣称 M1R-B 完整持续协作。真实办公仍按 PC-01 与外部适配验收，内部回放不替代真实接入。详见[专项方案](./2026-11-02-router-executor-autonomous-dispatch-plan.md)。

单维护者与 AI 默认同时只有一个待合入承重切片。已有验收及质量门持续回归。日历日期待真实授权、PC-00 能力结果与 migration 评估明确后填写，不用未经测量的“直接复用比例”估工期。

## 9 工程验收与质量评估

### 9.1 核心判据

| 场景 | 必须出现的证据与失败条件 |
|---|---|
| 正常工作自动形成上下文 | 原办公保存/发言或既有执行入口触发，无额外发布上下文接口；来源版本、协调水位、引用和读面一致 |
| 准入快慢分流 | 来源拒绝、重复与确定性状态更新不进入 Router 语义评估；需理解的候选批量读上下文；遗漏与误收分别归因 |
| 已承接工作快路径 | 已订阅线程无 @ 的普通补充直接到正确工作，不新增 Router 语义评估；准确版本在合法执行边界被真实消费，只有接收回执不得通过 |
| 新缺口慢路径 | 从多人多条讨论恢复目标，自动补上下文并与已有工作去重；授权内新研究可选 Agent、建立必要 Task/约定及草稿，不要求人补执行提示词或建任务 |
| 消息编辑与乱序 | 同 message_id 新正文形成修订；重复不重提取/提醒；旧通知不覆盖新版；补不齐显示缺口 |
| 持续协调与 M:N | 一个线程变化送至两个已关联工作；无关工作不收；未决问题跨唤醒/重启保留且只读参考不变成执行指令 |
| 新旧 Agent 依据 | 旧 Run 真实输入/消费是旧预算，变化产生影响提示，新 Run 实际用新预算；指令保持相同，缺任何一层失败 |
| 建议、身份与决定 | 建议不误升级；未知平台身份不自动映射成员；有真实业务确认才能关联决定；自报完成不冒充成果验收 |
| 执行边界 | 有效 Mandate 内可自主研究/分析/草稿派工；仅有订阅、@Agent 或资料可读不得起 Run；恶意输入、旧授权和越权现场被拒；旧 Run 不复活 |
| 自主派工与 Agent 选择 | 硬条件筛选、合法现场、无重复派工、单活跃和总预算通过；无需逐次派工确认，不能用模型自评能力或 full_access 绕过限制 |
| 草稿与人工介入 | 草稿保持授权受众，正式发布/外发/业务承诺需人决定；等价候选与临时离线不反复询问，业务冲突/扩权/未知副作用才升级 |
| 撤回与撤权 | 正文、分页/缓存、合并理解、提醒和历史正文读面一并受限；旧代次延迟模型结果不能提交 |
| 失败、纠正与恢复 | 模型失败、离线、限流、额度耗尽、超限和重启有对应状态；同输入重试不重复、不复活已纠正结论 |
| 来源及模型隔离 | 私有 Session/候选/目录、未授权项目、凭据和设备路径不进模型团队上下文、读面或证据；工具限制有真实装配负控 |
| 人的负担 | 普通授权内场景新增执行提示词、人工上下文搬运、逐事件规则与手工补建 Task 均为 0；首次授权与真实业务决定单列，静默不能以漏做工作换取 |

组合场景固定为“轮椅需求补充进入已有方案工作”与“跨成员讨论暴露接驳研究缺口”，同时保留预算错版、无关/假设静默、超范围退回、撤权和断线变体。已存在 Task 的 A 切片不承担自动新工作的通过结论；完整组合必须覆盖后者。

### 9.2 六原语与证据

驱动走生产 HTTP/WS、真实 Hub/Node/Runtime 包入口与两套独立成员会话。前置状态只能由正常业务动作或生产来源协议形成；不直插业务表、不用源码入口替代生产包解析。

外部供应商边界允许协议服务回放，模型出口允许 DSH replay，业务权限、版本、协调事务、投影与输入装配仍走真实实现。真实平台烟测、真实模型质量与真人试用分别留证；某一层未跑保持 not_run。

观测沿既有分层，新增建议为 `node.source`、`hub.context`、`node.context-analysis`、`runtime.bridge.context`、`web.project-context`。实现时以 ADR-0025/0026/0027 登记的 `hub.context`、`node.source`、`node.coordination`、`node.context`、`runtime.bridge.context` 为准；本文候选名不当作已有事件。保持 trace/run/command 及 revision/thread/evaluation/snapshot 身份；拟议链增加 workKey、投递/消费、快慢路径及原因、Router 语义调用、Mandate 版本、DispatchDecision、WorkIntent 和同因预算身份。分别核对事件收到、合法交付、选入执行、真实消费和被拒绝的水位，不能以消息到了 Hub 推断 Agent 已采用。

驱动与独立判定分开：交叉核对来源版本、Hub 状态、浏览器读面、Node 字节及 Runtime 请求/行为；缺数据失败。以单点变异证明漏引用、错版、来源撤权、权限提升、重复提醒和终态复活会判红。只断言某个上下文 ID 或正文字符串存在，不算消费完成。

证据脱敏存 `artifacts/evidence/project-context/<scenario>/<attempt>/`，每次独立 manifest，保留失败尝试，不能读取旧成功结果冒充本轮。完整源聊天、文档、模型请求、凭据与绝对路径不进公共包。各切片把复跑入口、判据和归因挂到 `docs/agent/README.md` 与取证地图。

### 9.3 质量门

依[门禁分级](./2026-10-08-q-gates-g0g1g2-tiers.md)运行受影响门：领域/协议 Q0/Q1，Hub/DB 加 Q2，Runtime 兼容与能力限制加 Q3，认领/断连/恢复加 Q6，来源权限/模型工具/投影加 Q7，交互加相关 Q5。新增依赖固定精确版本并过边界与许可检查；DSH 升级单独验。

组合驱动、独立判定、协调语义评估与真实平台只读烟测是待建交付物，命名及退出码在对应 Issue 固化后才登记为可运行。本次上游隔离测试不计为这些门的通过结果。正式发布继续执行既有发布级 Q5、Q8/Q9 及相关全量门。

### 9.4 协调质量和成本

开发集与保留集分开，至少覆盖活动筹备、客户方案、经营汇报。由人核定来源、已知依赖、建议/决定、问题及预期影响；加入多任务同线程、无关噪声、冲突、晚到、撤回、未知身份、缺材料与恶意指令，不能让待测模型自编答案再自评。保留集加入职责内但未写入逐事件规则的新变化，冻结职责/模板/提示配置后再测试，防止靠针对案例手工配置伪装理解。

工程链采用 replay；真实模型评估固定 Provider/版本、提示/规则版本及输入身份。分别报告有依据事实、建议误升级、错误归属、问题遗忘、影响推荐精确率/召回率、错版、提醒数、输入量、调用数、延迟和费用。高风险标注样例要求零假决定和零无来源硬事实，明确依赖不能混入推测。其他阈值先在开发集测量，在查看保留集前冻结，不事后换样例。

另报已订阅普通补充进入 Router 语义评估的次数、快路径交付/消费成功率、新工作漏识别/误派、变化至消费及草稿就绪时间，以及新增执行提示词、人工搬运、手工建 Task 和不必要提问数。Executor 理解补充的模型调用与 Router 路由调用分别计费和归因。少调用、少提醒须与工作覆盖和成果质量一起评价。

初始工程目标：内容成功读入后，确定性更新 p95 ≤10 秒，协调理解更新 p95 ≤60 秒；注明事件规模与机器环境。平台通知、限流、补拉等待、Node 离线和模型排队单独报告。自动模型并发默认 1，按相关变化合并；日额度、输入上限、超时与唤醒策略在启用前明确。目标是试验判据，不外推性能承诺。

## 10 真人试用与阶段退出

先本人双账号演练，随后至少一位真实协作者参与真实工作。三类办公情境复用同一来源/线程/订阅/版本/协调机制，不分别写成三个固定业务工作流。

与原办公工具＋个人 Agent 的正常用法比较，允许对照使用搜索、总结、模板和文件读取。事前固定成果要求、材料变化及计时边界，记录双方主动劳动、重复解释、误解、错版返工、求助/放弃、等待、提醒、额外确认、配置与维护。额外提示词指为了让 Agent 开始、继续或补背景而新增的指令，和正常业务讨论分别记录；人工复制上下文、补建 Task、逐事件配置及纠正机器单列，不能只计算接收者省时。

| 里程碑 | 退出条件 | 未通过时如何处理 |
|---|---|---|
| M0 复用与架构成立 | PC-00 给出可迁文件、事务/权限映射和 rc.8 受限运行证据；#451～453 形成已采纳决策。PC-01 的外部状态单列 | 缩小迁用面或单独评估 DSH 升级；不以依赖升级代替机制验证 |
| M1a 内部协调薄链 | 两成员内部工作事件自动关联；问题持续保留；影响到人；后续新 Run 消费新版本，负控通过 | 修复断层；薄概览或单个上游测试通过不算闭环 |
| M1R-A 已有 Task 自主续接 | RD-01～03 与受限模型/工具、PC-05b 成立；合法订阅到工作收件箱，在 Run 边界自动消费并产私有草稿，无逐次确认 | 这是工程过渡；不宣称新工作自动承接已完成，未补齐撤权/回执恢复/清理时不启用 |
| M1R-B 快慢路径持续协作 | RD-04/05 接到同链：已承接补充直通，新缺口自动路由并建立必要工作；无新增执行提示词、搬运、逐事件规则或手工补建 Task，负控通过 | 只有通知、收件箱接收或人为替系统补指令时失败；同 Run 动态输入不是此里程碑的必要前置 |
| M1b 真实办公闭环 | PC-01～07 接通普通讨论＋至少一种云资料、撤权与缺口；同一主链真实跑完 | 授权/接口阻塞保持未完成，必要时换候选；不靠手工转发代替 |
| M2 真人价值可判断 | M1R-B 与真实办公链可用；三类情境、至少一对真人完整成本/质量比较；提示词、搬运和打扰减少且覆盖/质量不退化 | 若误报、漏做和维护抵消收益，优先修正主链；无有效比较则保留未验证 |
| M3 可发布 | 安装/迁移、暂停/撤销、费用、恢复、覆盖说明及发布门齐备 | 先内部版，Alpha 按既有发布规则推进 |

M1a、M1R-A/B 与 M1b 是工程结论；M1R-A 不能替代 M1R-B，M2 才判断真人协调收益。真实使用尚未开始时保持 not_run，不用 Issue 关闭率、更多连接器或自动 Run 数量代替产品结果。
