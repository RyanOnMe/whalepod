# 运行完成通知验收（P1-UX-13 / #259，父账 #243 后续·P1-UX 三期刀一）

## 这条切片改变什么

Run 一跑几十分钟，人离开这个 tab 就不知道跑完没有——回来先逐个刷新看状态。
本切片把已经在链路上的 `run.changed` 终态变成「有人看着」的三件事：

1. **tab 标题徽标** `(N) WhalePod`（N = 未读终态运行数）；进任务房间或点通知即已读；
2. **系统通知**（可选开关）：只在「当场发生」且用户开过提醒时弹；点通知 → 窗口 focus + 进任务房；
3. **已读水位**落 localStorage——这是本切片的要害，见下节。

对照 ChatGPT 桌面端（#243 取证）：完成有徽标、离开有通知。**纯 Web，零协议改动**：
`run.changed {runId, taskId, status}` 本就全团队广播（packages/protocol/src/client-events.ts:33
注释：eventVisibleTo 只对 run.event 分受众），终态是 completed/failed/cancelled/lost。

## 要害：刷新会重放 24h 窗口

`CursorStore` 是**纯内存**的（apps/web/src/shared/realtime/cursor-store.ts:4：「页面刷新后从 0
重放保留窗口即可」——对缓存失效无害，对通知是灾难）：页面每次加载都会重新收到窗口内所有
持久事件。所以：

- 去重集合 `known`（FIFO 上限 300）与未读 `unseen`（上限 50）落 localStorage
  （`whalepod.notifications.v1`）；不合形半截 JSON 一律当空状态（宁可多数一次，不能整块卡死）。
- 「当场发生」= 帧 `occurredAt ≥ 本次挂载时刻 − 60s`（`LIVE_TOLERANCE_MS`）：**历史重放只进
  徽标、不弹系统通知**——打开页面被 24 小时前的旧事弹一脸是最典型的通知骚扰。
  容差 60s 是给服务端/浏览器时钟偏差与建连延迟留的。
- 反向判据同样重要：**刷新后未读还在**（徽标是「你不在时欠你的」），而不是靠这次重放重建。

## 驱动与判定

- **Q1 web**（`apps/web/tests/run-notifications.spec.tsx`，7 例，走真实壳 + 真实 router +
  真实 query client）：替换 socket 工厂捕获 RealtimeBridge 组装的回调、手推**真实帧**——
  与浏览器走同一条帧处理路径，不开测试专用近道。
  1. 终态进徽标；同一 runId 不重复；非终态不算；
  2. 进任务房间清零 + 事后重放不补记 + 正开着的房间新完成不积未读；
  3. 重放不弹 / 默认关不弹 / 授权且当场才弹 / 点通知进房并已读；
  4. 刷新（内存态丢弃、存储保留）：未读存活 + 同窗口重放不叠加 + 新 Run 照常计；
  5. 任务名取不到用「任务」占位；6. 不支持 Notification → 不渲染开关、徽标照常；
  7. 权限被拒 → 一行说明、不弹、徽标照常。
- **变异自测**（`#257` 起的规矩：门要能被证伪）——四刀全部打红：
  | 变异 | 结果 |
  |---|---|
  | 掐持久化（`setItem` 改 `void 0`） | 红（刷新用例） |
  | 掐「正看着的房间不积未读」 | 红 |
  | 掐「默认关」闸（只看 granted） | 红 |
  | 掐「重放不弹」判定（`if (!live) return` 删除） | 红（补了「开关已开时的重放帧」用例后才红） |
- **Q0**：`pnpm check` 全绿（111 文件 1375 过 / 7 预期失败为既有深色 `it.fails` 债）。

## 踩坑记录

1. **初版「刷新重放」用例是盲的**——只断言「重放同一 runId 后仍是 (1)」，而从零重建也会数成
   (1)：掐掉持久化的变异照样全绿。真正的判据是**重放之前**标题就已经是 `(1)`（未读跨刷新存活）。
   变异自测抓到的第一条真问题就是这个，写下来：**断言要能区分「记住了」和「重算一遍正好一样」**。
2. **回调捕获工厂必须在 `render` 之前装**：RealtimeBridge 的连接只在挂载时建一次，
   render 之后再 `setRealtimeSocketFactoryForTest` 拿不到回调（代理会直接抛「尚未挂载」）。
3. **「默认关」会遮住「重放不弹」**：没点开关时当然不弹，于是 replay 判定删掉也不红——
   顺序要摆成「先开开关、再推一条历史帧（新 runId，排除去重解释）」。
4. 通知点击里的 `window.focus()` 在 jsdom 是 "Not implemented"（stderr 噪声，不影响断言）。

## 边界与债

- **页面不活着就弹不了**：没有 service worker、不做推送订阅——已文档化，不假装能做。
- **全团队口径**：谁的 Run 跑完全队都进徽标（与 run.changed 广播口径一致，零协议改动）；
  「只通知我相关」需要 owner 查询与口径定义，不做。
- **多标签页各自计数**（localStorage 无跨标签锁，可能各弹一次）；不引服务端未读水位。
- **开关只在宽屏侧栏**（窄屏没有侧栏，窄屏用户暂时只能享受徽标）；徽标本身宽窄屏都在
  （无头组件挂在 AppShell，不挂在侧栏）。
- Notification 权限 `granted` ≠ 用户想要：**默认关**，点铃铛才请求权限、才写偏好。
- 未读上限 50 / 去重上限 300：超出按 FIFO 丢弃（24h 窗口内 300 个终态 Run 属不现实场景，
  真的到了也只是徽标少几条，不会说谎）。
