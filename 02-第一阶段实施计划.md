# TabTin 2.0 第一阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施。每一步使用 checkbox 跟踪；每个 Task 完成后必须经过独立评审门。

**Goal:** 从空仓库构建一个可自托管的单 Team 产品，让两个真人成员围绕一个 Task 驱动两个长期 Agent，经 Device Node 上的隔离 DSH Runtime 完成审批、Artifact 发布、Reviewer 复核、取消和重跑闭环。

**Architecture:** 一个 TypeScript 模块化单体 Hub 拥有团队事实并使用 PostgreSQL；浏览器通过 HTTP 与下行 WebSocket 协作；成员设备上的 Node 通过出站 WebSocket 接收 Run，按 Run 启动一个独立 DSH Runtime；`@tabtin/runtime-dsh` 是唯一允许依赖 DSH 的 Adapter。

**Tech Stack:** Node.js 24、pnpm 11.7、TypeScript 6、Fastify 5.12、PostgreSQL 18、Drizzle 0.45、Zod 4.4、React 19.2、React Router 8.3、TanStack Query 5.101、Vite 8.2、Vitest 4.1、Playwright 1.62、DSH `@deepseek-ai/dsh@0.1.0-rc.6`。

## Global Constraints

- 所有路径均相对于全新的 TabTin 2.0 仓库根；不得在 TabTin 1.x 仓库内实施。
- 一个部署实例只允许一个 Team；所有成员可见所有 Project。
- Node.js 固定 24.x；`packageManager` 固定 `pnpm@11.7.0`；TypeScript 开启 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`。
- Hub、Web、Node 与 Runtime 只通过 `@tabtin/protocol` 共享 wire；`protocolVersion` 固定为 1。
- 只有 `packages/runtime-dsh/**` 和 `apps/runtime/**` 可以 import `@deepseek-ai/dsh-*` 或 `@deepseek-ai/cordis`。
- DSH 直接依赖使用精确版本；禁止 semver range、tag 与 deep import。
- 第三方插件只进入 Runtime 子进程；Hub 和 Node 主进程不得动态 import 插件代码。
- Workspace 绝对路径和模型密钥只保存在 Node；Hub 数据、日志、WebSocket 和 Evidence 中不得出现。
- PostgreSQL 是唯一团队数据库；不得增加 Redis、Celery、Kafka、RabbitMQ 或独立微服务。
- Run 状态、Task 状态与 DSH Session 状态保持独立；任何投影关联必须使用稳定 ID。
- Token delta 只实时转发，不写 PostgreSQL；持久事件单条 payload 上限 32 KiB。
- Artifact 单文件上限 50 MiB；Blob 按 SHA-256 内容寻址。
- 所有非安全 HTTP 方法校验 exact Origin；Browser WS 校验 Cookie + Origin；Node WS 只接受 Device Token。
- 每个代码 Task 先写失败测试、确认失败原因、做最小实现、跑受影响测试、再提交。
- 第一阶段正式支持 Linux Hub 与 macOS/Ubuntu Node；Windows Node 仅 experimental。
- 开源许可证为 Apache-2.0；公开前保留一次权利人法律审阅门。
- 不实现多租户、计费、Project ACL、群聊、协作文档、表格、移动端、Electron、DSH 前端插件或透明 Runtime crash resume。

const DSH_PREFIXES = ['@deepseek-ai/dsh-', '@deepseek-ai/cordis']
const DSH_OWNERS = ['packages/runtime-dsh/', 'apps/runtime/']

export function validateImport(importer: string, specifier: string): void {
  const isDsh = DSH_PREFIXES.some(prefix => specifier.startsWith(prefix))

  if (isDsh && !isOwner) {

  }
}

```ts
// packages/domain/src/run.ts
export type RunStatus =
  | 'queued' | 'dispatching' | 'running' | 'waiting_approval'
  | 'cancel_requested' | 'completed' | 'failed' | 'cancelled' | 'lost'

export type RunEvent =
  | { type: 'dispatch_acked' }
  | { type: 'runtime_ready' }
  | { type: 'approval_opened' }
  | { type: 'approval_closed'; remainingPending: number }
  | { type: 'cancel_before_dispatch' }
  | { type: 'cancel_requested' }
  | { type: 'cancel_confirmed' }
  | { type: 'completed' }
  | { type: 'failed' }
  | { type: 'lease_expired' }

const NEXT: Record<RunStatus, Partial<Record<RunEvent['type'], RunStatus>>> = {
  queued: { dispatch_acked: 'dispatching', cancel_before_dispatch: 'cancelled', failed: 'failed' },
  dispatching: {
    runtime_ready: 'running', cancel_requested: 'cancel_requested',
    failed: 'failed', lease_expired: 'lost'
  },
  running: {
    approval_opened: 'waiting_approval', cancel_requested: 'cancel_requested',
    completed: 'completed', failed: 'failed', lease_expired: 'lost'
  },
  waiting_approval: {
    approval_closed: 'running', cancel_requested: 'cancel_requested',
    failed: 'failed', lease_expired: 'lost'
  },
  cancel_requested: { cancel_confirmed: 'cancelled', failed: 'failed', lease_expired: 'lost' },
  completed: {}, failed: {}, cancelled: {}, lost: {}
}

export function transitionRun(run: { status: RunStatus }, event: RunEvent) {
  if (event.type === 'approval_closed' && event.remainingPending > 0) return run
  const status = NEXT[run.status][event.type]
  if (!status) throw new DomainError('INVALID_RUN_TRANSITION')
  return { ...run, status }
}
```

export async function transactCommand<T>(
  db: Db,
  key: CommandKey,
  execute: (tx: Tx) => Promise<T>,
): Promise<T> {
  return db.transaction(async tx => {
    const prior = await commandReceipts.find(tx, key)
    if (prior) return prior.result as T
    const result = await execute(tx)
    await commandReceipts.insert(tx, key, result)
    return result
  })
}

## 执行时的通用 Review 门

每个 Task 不以“代码写完”为结束，而以以下四项证据齐全为结束：

1. 该 Task 列出的失败测试确实在实现前因预期原因失败，实现后通过。
2. 一位未参与该 Task 实现的评审者核对产品语义、模块边界、权限与失败路径。
3. `pnpm check` 和该 Task 标准命令全绿，且未借助 skip、retry、降低断言或扩大权限过门。
4. 提交只包含该 Task 文件，提交信息与 Issue 目标一致，Evidence 不含 secret 或私有路径。

## 第一阶段终止判定

只有 Task 1–20 全部通过并满足 [04-验收矩阵与测试策略.md](./04-验收矩阵与测试策略.md) Q0–Q9 时，第一阶段才算完成。以下任一情况必须暂停新功能并回到 ADR/风险复盘：

- DSH 公共契约无法稳定实现 Agent 控制、审批拦截、事件投影或插件注册中的任一项。
- 不能证明原始 Session、Workspace path、凭据和未发布 Artifact 对非 owner 不可见。
- Hub/Node 重启后会丢失已确认的团队事实，或重放会产生二次操作。
- 未修改的受审 DSH 插件无法通过 Plugin Pack 运行。
- 两个真人无法在不触碰对方 Workspace 的情况下完成 Builder→Artifact→Reviewer 闭环。
- 模块化单体在目标负载下达不到性能门，且 profile 不能定位为单一深模块问题。

上述门禁未全绿时，不得以“Alpha 可以不完美”为由宣布第一阶段完成。
