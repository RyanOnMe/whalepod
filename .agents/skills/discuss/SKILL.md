# 研讨模式（discuss）

适用：还在梳理、调研、对齐方案，没有要合并的代码。

## 规则

- 可以读代码、读文档、跑只读命令、用探针看现场。
- **不主动提交、不推送、不开 PR、不改分支**，除非用户明确说「提交」。
- 笔记直接记在对话或当前分支的文档里；研讨产物要变成行动时，用 skill `file-issue` 登记。
- 方案不稳就把问题问狠一点再动手：假设是什么、怎样算错、最小验证是什么。
- 涉及承重决定（状态机、协议、权限、隔离模型）的结论，提醒用户走 ADR（`docs/adr/`），不要在某个实现 PR 里静默改模型。

## 收口的几种去向

- 聊清楚了要动手 → 转 `dev-main`。
- 发现一个独立问题 → `file-issue`，只记账，这轮不改。
- 想法太大 → 先收成需求再拆 Issue（纵向拆分，一个 Issue 一个 squash PR）。
